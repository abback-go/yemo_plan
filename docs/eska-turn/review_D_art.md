## 1. 고칠 것 (심각도 순)

심각도: **A** = 정보가 가려지거나 깨져 보임(다음 라운드 꼭) · **B** = 대마법·상태가 의도대로 안 읽힘 · **C** = 다듬기.

### A1. 다단 대마법 피해 숫자가 금빛 덩어리로 뭉개짐 — A
- 스크린샷: `turn_ult/ult_fulgur_c_fx`·`d_hit`, `turn_ult/ult_harpe_c_fx`·`d_hit`, `dense/ult_fulgur_057~120`, `dense/ult_harpe_*`
- 원인: `THud.pop()` 다단 비켜 쌓기가 `Vector2(8, 10) * k` — 24px 글자("big"·"crit")에 8·10px씩만 비켜서 5~6개가 거의 그대로 겹친다. 철퇴(5타)·종막의 검(6타)에서 "1,234,567 / 2,469,134 / …"가 한 덩어리가 되고, 금 글자 + 금 번개 + 베이지 섬광 위라 대비도 없다.
- 수정안: 한 행동에서 같은 대상의 다단은 **숫자 하나를 이어서 키운다**.
  - `pop()`에서 같은 `key`의 살아 있는 숫자가 있으면 새로 넣지 않고 그 항목의 `text`를 합계로 바꾸고 `hits += 1`, `age`를 0.2까지만 되돌림, 글자 크기 +2px(최대 +8). 오른쪽 위에 작은 "5타"(10px) 꼬리표.
  - 이미 같은 방식이 `PVfx.Numbers`(`proto/p_vfx.gd`: `MERGE`·`HOLD_AGE`·`GROW_MAX`)에 있다 → 그 규칙·상수를 그대로 따른다(DRY).
  - 마지막 타에서 합계 숫자를 0.08초 1.3배로 튕기고 `tn_crit` 한 번.
  - 개별 타격 값이 꼭 필요하면 작은 12px 회색으로 몸 쪽에 0.3초씩만 띄운다.

### A5. 새 효과음 대부분이 폰 스피커에서 거의 안 들림 (저역 위주) — A
- 근거: §7 측정. 300 Hz 고역 통과(폰 스피커 근사) 뒤 RMS가 `tn_wave` −14.3 → **−35.5 dBFS**, `tn_guts` −17.6 → **−35.2**, `tn_ult` −14.2 → **−30.7**, `tn_ult_hit` −14.8 → **−29.9**. 폰에서는 대마법 소리가 차례 알림 `tn_turn`(−30.3)과 비슷하고, 웨이브 북·근성 심장은 바퀴 클릭(`tn_select` −26.8)보다 작다. 반대로 `tn_dispel`은 −21.2로 **폰에서 가장 큰 새 소리**(대마법보다 9 dB 큼).
- 원인: 무게를 28~95 Hz 사인(`f0 = 90 → 28`, `55 → 42`, `95 → 52`, `70 → 45`)이 맡는다. 폰 스피커는 이 대역을 거의 못 낸다.
- 수정안(각 소리에 층 하나씩 더함 — 배음으로 "낮다"는 느낌을 폰에서도 냄):
  - `tn_ult`: `{wave = "saw", f0 = 110.0, f1 = 98.0, dur = 1.2, vol = 0.10, lp = 0.25, attack = 0.15, decay = 0.8}` + `{wave = "sine", f0 = 220.0, f1 = 196.0, dur = 1.0, vol = 0.12, attack = 0.1, decay = 0.9}`
  - `tn_ult_hit`: `{wave = "tri", f0 = 220.0, f1 = 80.0, dur = 0.45, vol = 0.30, tau = 0.12}` + `{wave = "noise", dur = 0.35, vol = 0.30, bp = 700.0, bp1 = 250.0, q = 0.4, decay = 1.6}`
  - `tn_wave`: 북 두 번마다 `{wave = "tri", f0 = 190.0, f1 = 104.0, dur = 0.3, vol = 0.35, tau = 0.09}` (두 번째는 `delay = 0.18`) + 가죽 소리 `{wave = "noise", dur = 0.08, vol = 0.35, bp = 600.0, q = 0.5, decay = 2.5}`
  - `tn_guts`: 두-근에 `{wave = "sine", f0 = 210.0, f1 = 135.0, dur = 0.12, vol = 0.30, tau = 0.04}` (두 번째 `delay = 0.17`)
  - `tn_dispel`: 첫 잡음 `vol 0.55 → 0.35`
  - 목표(300 Hz 고역 통과 뒤 RMS): 대마법·대마법 맞음 약 −20, 웨이브·브레이크 약 −22, 근성·해제·도발 약 −24, UI 약 −27. 측정 스크립트는 §7 끝.

### B1. 11025 Hz로 만든 소리의 대역 필터가 2205 Hz에서 막힘 + FM 겹침(aliasing) — B
- 원인: `_render_fast()`의 `bp_max := rate * 0.2`. 11025로 만든 `tn_ult`·`tn_ult_hit`·`tn_dispel`·`tn_wave`·`tn_guts`는 대역 중심이 2205 Hz를 못 넘는다.
  - `tn_dispel`: "높은 데서 낮게" 4200 → 500 쓸림이 앞 약 45% 동안 2205에 붙어 평평하고, "흩어지는 반짝임" 층(`bp = 7000`)은 2205의 흐린 쉭 소리가 된다.
  - `tn_ult`: 800 → 3200 오름이 중간부터 멈춤. `tn_ult_hit`: 3000 → 600 내림의 앞이 잘림.
  - `tn_ult`의 종 층 `f0 = 2349, fm = 2.76`은 변조 주파수 6483 Hz가 나이퀴스트(5512)를 넘어 겹친 잡음이 섞인다(1568 층도 옆띠 5896 Hz가 넘음).
- 수정안: 반짝임·종 층만 22050으로 따로 만든다 — `tn_ult_bell`(22050, 종 두 층)·`tn_dispel_glint`(22050, 7000 반짝임)을 새로 두고 `tn_ult`·`tn_dispel`을 부를 때 같이 재생. 저역 층은 11025 그대로(시작 시 합성 시간 유지).

### B2. 대마법 12개의 소리가 거의 같음 · 시간의 정적에 폭발음 — B

## 8. 종료 시 엔진 누수 경고 — 원인 (관점 ⑧)

결론: **단계 D의 `Fireball` 변경과 관계없다. 단계 C(`29c61a2`)부터 같은 경고가 있었고, 원인은 두 가지다.** 실행 중 누수가 아니라 종료 순간 정리 순서 문제라 웹 플레이에는 영향이 없다.

### 8.1 텍스처 8~13 · TextLine · ShapedText · FontAdvanced → `TTheme._fonts` 정적 캐시 (확정)
- `t_theme.gd`의 `static var _fonts := {}`(FontFile 4개)와 `static var _box: StyleBoxFlat`이 종료 때까지 글꼴을 붙잡는다. 글꼴은 `draw_string` 결과를 `TextLine` 캐시와 글리프 아틀라스 텍스처로 들고 있어 함께 남는다.
  - 남는 텍스처 131072바이트 = 256×256 × 2바이트(글리프 아틀라스), 174762 = 그 밉맵 포함.
  - 그린 글자·크기가 많을수록 아틀라스 장 수와 `ShapedText` 수가 는다(프레임 5에서 종료 61 → 시나리오 끝 104~145). **그래서 `Fireball` 고침 뒤 "늘었다"고 보인 것은 그 시나리오가 그린 글이 달라졌기 때문**이다: 같은 장면에서 `basic_fire`를 쏘고 끝내도 ObjectDB 295 → 296, ShapedText 87 → 88 (글 하나 차이).
- 증명: 검토자 사본에서 `TStage._exit_tree()`에 `TTheme._fonts.clear(); TTheme._box = null`만 넣고 `turn_proto.tscn`을 60프레임 돌림 → GL 텍스처·ShapedText·FontAdvanced·TextLine·FontFile 누수가 **모두 사라짐** (ObjectDB 234 → 156).
- 수정안: `TStage`(또는 `TTheme`에 `static func release()`를 두고 `TStage._exit_tree()`·편성 장면 `_exit_tree()`에서 부름)에서 위 두 줄. `TWitchArt._rim_mats`·`_rim_shader`는 비워도 숫자가 안 줄어 원인이 아니다.

### 8.2 GDScript 약 110 · `player.tscn` PackedScene · RectangleShape2D 2 → 시제품 공용 스크립트의 의존 고리 (단계 D 무관)
- 빈 장면(`Node2D` 하나 + 자동 로드 7개)을 띄우고 끝내면 경고 **0**. 턴제 장면은 프레임 5에서 끝내도 남는다.
- 스크립트를 하나씩 `load()`만 하고 끝내기: `t_actor`·`t_hud`·`t_stage`·`t_setup`·`t_witch_art`·`t_enemy_art`·`e_art`·`e_hud`·`e_move_fx`·`p_vfx`·`p_shot`·`p_dummy`는 혼자서도 남고(ObjectDB 145~164), `t_fx`·`t_data`·`t_icon`·`t_theme`·`p_draw`·`p_particles`·`palette`·`world.gd`와 **남는 목록에 든 스크립트 90개는 각각 혼자서는 0**. 즉 하나의 스크립트가 아니라 `PVfx ↔ PShot ↔ PDummy ↔ EArt ↔ EHud …`처럼 서로 참조하는 시제품 공용 스크립트 고리가 `world.gd`(→ `PLAYER_SCENE := preload("res://player/player.tscn")`)까지 끌어오고, 종료 때 엔진이 이 고리를 끝까지 풀지 못한다. 두 스크립트만의 순환 + 정적 변수를 따로 만들어 본 실험에서는 재현되지 않아 정확한 고리 한 곳은 못 짚었다.
- 단계 C 커밋 `29c61a2`에서 같은 장면: ObjectDB 234 · resources 98 · Texture 8 · ShapedText 61 · FontAdvanced 4 — **HEAD와 숫자가 같다**.
- 수정안: 급하지 않다(종료 때만, 웹은 탭을 닫음). 없애려면 `TActor`가 `EArt`(실시간판 에스카 그림)를 직접 참조하는 부분을 턴제 쪽 복사본/인터페이스로 끊는 것이 가장 효과가 클 것으로 보인다(`t_actor`·`t_witch_art`가 고리에 들어가는 입구). 8.1만 고쳐도 남는 경고는 `ObjectDB 약 150 · resources 약 95 · Shape2D 2`로 줄어 "글꼴·텍스처" 줄은 사라진다.

## 9. 잘 된 것 (유지)
- 해류의 성소 물 돔, 심연 붕괴 소용돌이, 시간의 정적 큰 시계 + 적 머리 위 모래시계 — 효과가 그림 그대로 읽힌다.

- 해제: 패널의 버프 아이콘이 튀어 흩어져 "무엇을 잃었는지"가 보인다.
- 웨이브: 적이 걸어 들어오고 보스 웨이브는 하늘이 붉어지며 땅 울림.
- 컷인 띠: 마녀마다 색·문장 무늬가 달라 누구 대마법인지 0.2초 안에 알 수 있다.
- 실행 중 오류 0 (6개 시나리오 + 검토자 시나리오 3개).
