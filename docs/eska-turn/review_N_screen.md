### 높음

**N-01. 바퀴 → 고정 마법 줄 [제안 — 사용자 확인 권장: 바퀴 모양은 단계 C에서 정한 것, 칸 구성(공격 + 장착 4 + 대마법 [확정 8-1·13-1])은 그대로]**
- **문제**: `THud._build_slots` — 칸 중심 = 마녀 몸 가운데 + 반원 R 78(`WHEEL_R`). `TStage.WITCH_AT` 간격 62 → 가운데 마녀(160, 258) 차례면 1번 칸(약 (97, 212))이 뒤 마녀(98, 228)의 머리·몸통에, 5번 칸(약 (238, 212))이 앞 마녀 모자에 앉는다. 앞 마녀 차례면 대마법 칸이 첫 적·피해 숫자와 겹친다(`k07`: 심연 붕괴 칸이 두꺼비·"크레딧 +1" 글 위). 마녀 차례마다 **원판 6개 + 흐린 마녀 2명**이 섞여 화면 가운데가 가장 지저분하다.
- **FGO §21.3**: 스킬은 **화면 아래 줄 고정**(720p y 524..591 = 360 기준 **y 262..296**), 서번트 그림 위에 버튼이 뜨지 않는다. 엄지가 늘 같은 자리로 간다(§21.3 설계 의도).
- **안**:
  - 마법 줄 = 가로 6칸, **(left()+34, 262) ~ (left()+34+6×44, 298)**, 칸 지름 36(대마법 40), 간격 44, 터치 사각 40×40(대마법 44×44). 차례 마녀가 바뀌어도 자리 고정. 왼→오 = 기본 공격 · 장착 1~4 · 대마법(금테) — 지금 바퀴 칸 순서 그대로.
  - 줄 바탕: 먹 0.85 띠 (left()+4, 258, 298, 42) 모서리 4 + 왼쪽 끝 (left()+8, 268)에 차례 마녀 얼굴 칩 22px(`TActor.Snap`) — "누구의 마법인지".
  - 마녀 대열을 **36px 위로**: `WITCH_AT` (222, 252) · (160, 222) · (98, 192). 발밑(그림자 포함 ≤ 256)이 줄 위 끝 258에 닿지 않는다. 뒤 마녀 모자 꼭대기는 약 y 117 — 적 카드(x ≥ 328)·행동 띠(y 32~50)와 안 겹침.
  - 넓은 화면이면 대열을 빈 땅 쪽으로: 마녀 x − `ofs.x × 0.5`(800 폭이면 −40) → 간격을 62 → 74로(뒤 마녀만 더 왼쪽). 바퀴가 없어지니 옆 마녀가 가려질 일이 없어 간격은 아트 판단.
  - 설명 띠·대상 고르기·"다시 누르면 실행"(§21.15)·봉인 자물쇠·비용 배지·연쇄 꼬리표는 칸 자리만 바뀌고 규칙 그대로.
- **대안(작은 수정)**: 바퀴를 두되 ① 중심을 머리 위(`actor.head() − (0, 10)`)로, ② 각도 −165°~−15°, ③ 칸과 겹치는 이웃 마녀는 알파 0.35. 그래도 뒤 마녀 모자와 1번 칸이 닿는다(간격 62에서는 피할 수 없음) — 그래서 고정 줄을 추천.
- **시험**: `turn_ui_wheel`·`turn_touch`·`turn_wide` 좌표 갱신. 바퀴 칸 사각과 모든 마녀 `body_rect`가 겹치지 않음을 `turn_rules_test` 대신 시나리오 `eval`로 확인.

## 4. N3 (폰 웹 전체 화면 · 가로 고정 · 세로 안내) — R1 뒤에도 필요한가

**필요하다. P1 그대로.**

| 상황 (CSS 크기 @비율) | 배율 | 보이는 논리 크기 | 풀 HD 전체 화면 대비 |
|---|---|---|---|
| 전체 화면 가로 20:9 (915×412 @2.625) | **3.005** | 799×360 | 100% |
| 브라우저 탭, 주소 막대 보임 (915×356) | **2.596** | 925×360 | 글·버튼 **−13.6%** |
| 세로로 듦 (412×915) | **1.689** | 640×1421 | **−44%** + 위아래 530px 빈 먹색 (`p1_portrait`) |

- R1(K-01)은 "창 안을 꽉 채우는" 배율만 바꿨다. 주소 막대는 창 높이 자체를 줄이고(시험에선 412 → 356 CSS px로 흉내), 세로 방향은 창 폭을 412로 만든다 — 배율 코드로는 못 고친다.
- 지금 코드에 전체 화면·방향 처리 없음: `game/proto/turn/`·`export_presets.cfg`에 `requestFullscreen`·`orientation.lock` 없음. 가로 고정은 홈 화면 설치 웹 앱(`progressive_web_app/orientation=1`)일 때만.
- 세로 640×1421에서는 R1 `ASPECT_EXPAND`가 세로로 넓어져 `ofs.y` = 530 — 턴제 층은 그 가운데 그려지고 위아래가 빈다. 전투에서도 같다. 세로를 지원하지 않으니(§21.16 "세로 화면은 지원하지 않는다") **세로 안내 덮개**가 맞다.
- 안은 review_M §5 N3 그대로(첫 터치에 `requestFullscreen()` 이 끝난 뒤 `screen.orientation.lock('landscape')`, 실패는 조용히 · 세로면 덮개 "가로로 돌려 주세요" 15px + 흐름 멈춤 · 설정 "전체 화면" 줄). 덧붙일 것: 전체 화면이 풀리면(`fullscreenchange`) 다음 터치에 다시 요청하지 말고 설정 줄로만 — 사용자가 일부러 나간 것일 수 있다.
- 시험: `web_turn.mjs`에 915×356(주소 막대) · 412×915(세로) 두 화면을 더해 덮개 유무·배율을 찍는다.
