## 2. 전투 콘셉트

플레이어는 이동하면서 근접 기본공격 3연타를 넣고, 긴 쿨타임의 신성을 판단해서 끼워 넣으며, 적의 공격은 이동과 대시로 피해 처치하고 자원을 얻는다.

- 플레이어의 행동: 이동·점프·대시로 위치를 잡고 기본공격으로 적을 처치한다.
- 적의 대응: 유형별로 접근, 원거리 견제, 돌진, 공중 추적으로 진로를 막는다.
- 전투의 목표: 탐험 동선을 막는 적의 제거다. 전투는 탐험과 부탁 수행의 수단이다. (00_게임 콘셉트 4-2)
- 보상 연결: 적 처치로 자원을 얻고, 자원은 신성 습득과 강화에 쓴다.
- MVP 범위: 기본 이동(좌우·점프·일반 대시), 근접 기본공격, 더블점프, 한 신의 신성 세트(수업 절차 없이 초기 보유로 지급), 능력 게이트, 일반 적 처치까지다. 보스·수업·회복 수단은 이후다. (00_게임 콘셉트 7절)

전투는 기본공격 위주로 유지한다. 신성 쿨타임을 길게 잡아 난사를 막는다. (참고 게임: 스컬)

## 3. 전투 기본 흐름

이 게임은 스테이지 클리어형이 아니다. 전투는 탐험 중 발생하는 **조우 단위**로 성립하고 종료된다.

기본 흐름: 탐험 중 적 조우 → 적 감지·추적 시작 → 플레이어 공격 입력 → 공격 판정 생성 → 고정 데미지 적용 → 적 HP 감소·넉백 → 적 HP 0 이하 → 적 Dead 전환 → 자원 1회 지급 → 조우 종료 → 탐험 재개

상세 설명: 플레이어가 적의 감지 범위 안에 들어오면 적이 추적을 시작한다. 플레이어는 D로 기본공격을 넣거나 Q/W/E/R/S로 신성을 사용한다. 공격 판정 안에 살아 있는 적이 있으면 해당 공격의 고정 데미지를 적용한다. 적 HP가 0 이하가 되면 Dead로 전환하고 자원을 한 번만 지급한다. 살아남은 적이 없으면 조우가 종료되고 플레이어는 탐험을 계속한다.
전투를 회피하고 지나가는 것도 허용한다. 플레이어가 감지 범위를 벗어나면 적은 복귀 상태로 돌아간다. 적을 모두 처치해야 다음 구역으로 갈 수 있는 강제 전투 구간을 둘지는 미정 (08_스테이지 설계에서 결정). 두더라도 "전투는 탐험 동선을 막는 장애물 수준"(00_게임 콘셉트 4-3절) 원칙을 상한으로 하며, 갇힘 방지를 위한 이탈 가능 여부도 08에서 함께 정의한다.

## 4. 플레이어 공격 기획

### 4-1. 기본공격 (D)

| 항목 | 내용 |
|---|---|
| 공격 입력 | D (누르는 순간). 방향은 캐릭터가 바라보는 방향 |
| 공격 종류·판정 방식 | 근접 3연타 콤보. 애니메이션 이벤트 시점에 전방 범위 판정 생성 |
| 판정 발생 타이밍 | 타수별 ComboStepHitTiming. 값 미정 (09) |
| 공격 범위·데미지 | 타수별 ComboStepRange, ComboStepDamage(고정값). 값 미정 (09) |
| 공격 쿨타임 | AttackCooldown. 값 미정 (09) |
| 콤보 초기화 | ComboResetTime 동안 재입력이 없으면 1타로 초기화. 값 미정 (09) |
| 가능·불가능 상태 | 가능: Idle, Move, Jump(공중), Attack(다음 타 연결 시). 불가능: Dash, Dead |
| 이동 허용 | 공격 중 좌우 이동 가능 |
| 애니메이션 | 타수별 Attack1 / Attack2 / Attack3 |

처리 흐름:

1. D 입력을 받고 상태와 AttackCooldown 경과 여부를 검사한다.
2. 조건을 만족하면 Attack 상태로 전환하고 현재 콤보 단계의 애니메이션을 재생한다.
3. ComboStepHitTiming 시점에 전방 판정을 생성하고, 판정 안의 살아 있는 대상에게 해당 단계의 고정 데미지를 적용한다.
4. 애니메이션 재생 중 또는 종료 후 ComboResetTime 안에 D가 다시 들어오면 다음 단계(1타→2타→3타)로 연결한다.
5. 3타를 마치거나 ComboResetTime이 지나면 콤보 단계를 1타로 초기화한다.
6. 애니메이션이 끝나면 이동 입력이 있으면 Move, 없으면 Idle, 공중이면 Jump(공중)로 돌아간다.

- 공격 중 피격돼도 공격은 취소되지 않는다. 콤보 단계도 유지된다.
- 하나의 판정으로 같은 대상에게 데미지를 두 번 적용하지 않는다. 판정마다 적중 대상 목록을 기록한다. 기본공격의 성장 경로(타수 추가, 데미지 상승 등)는 미정 (06_아이템·보상에서 결정)

### 4-2. 공격 신성 (Q/W/E/R/S)

| 항목 | 내용 |
|---|---|
| 구성 | 발현 중인 가호의 초급 2 + 고급 2 + 현계 1 = 5개. 배운 것 전부 사용 가능 |
| 소모 자원 | 없음. 쿨타임만 검사한다 |
| 데미지·사거리 | 신성별 DivinityDamage(고정값), DivinityRange. 근접·원거리 혼합. 값 미정 (09), 목록 미정 (04) |
| 상태 전환 | 사용 시 Attack 상태로 전환한다 |
| 가능 상태 | Idle, Move, Jump(공중) |
| 불가능 조건 | Dash, Dead, 쿨타임 진행 중, 미습득, 발현 중이 아닌 가호의 신성 |
| Attack 중 사용 | 미정 (사용자 확인 필요). 콤보 도중 신성으로 캔슬할 수 있는지 정하지 않았다 |
| 시전 중 이동 | 신성별로 다르다. 미정 (신성 목록 확정 후 09에서 확정) |

| 등급 | 개수 | 쿨타임 |
|---|---|---|
| 초급 | 2 | 약 10초 (가안) |
| 고급 | 2 | 약 20초 (가안) |
| 현계 | 1 | 60초 이상 (가안) |

쿨타임은 신성 사용 입력이 성립한 시점에 시작한다. **가호를 전환해도 쿨타임은 초기화되지 않고 계속 진행한다.** 전환으로 쿨타임을 회피할 수 없다.

## 5. 적 공격 기획

| 항목 | 내용 |
|---|---|
| 공격 조건 | 플레이어가 AttackRange 안에 있고 AttackCooldown이 끝났을 때 |
| 공격 대상 | 플레이어 1인 |
| 공격 범위·데미지·쿨타임 | 유형별 AttackRange, AttackDamage(고정값), AttackCooldown. 값 미정 (09) |
| 준비 시간·후딜레이 | AttackWindupTime, AttackRecoveryTime. 값 미정 (09) |
| 애니메이션·판정 타이밍 | 유형별 Windup → Attack → Recovery. 판정은 애니메이션 이벤트 시점(AttackHitTiming)에 발생. 값 미정 (09) |

| 유형 | 이동 | 공격 방식 |
|---|---|---|
| 근접 보행형 | 지상 보행 | 접근 후 전방 근접 판정 1회 |
| 원거리형 | 지상 보행, 거리 유지 | 일정 거리 밖에서 투사체 발사. 플레이어와 충돌하면 데미지 적용 후 소멸 |
| 돌진형 | 지상 보행 | 예고 동작 후 플레이어 방향으로 직선 돌진. 돌진 중 접촉 판정. 돌진 후 빈틈 |
| 비행형 | 공중 이동 | 지형에 막히지 않고 접근한 뒤 근접 판정 |
| 방어형 | 후순위 확장 | 이 문서에서 정의하지 않는다 |

모든 적 공격은 예고 동작 뒤에 판정이 발생한다. 예고 없이 즉시 판정되는 공격은 두지 않는다.

## 6. 데미지 계산 규칙

이 게임은 **고정 데미지형**이다. 계산식을 두지 않는다.

- 데미지 결정 방식: 공격마다 정해진 고정값을 그대로 적용한다. 최종 데미지는 해당 공격의 Damage 값이다.
- 두지 않는 요소: 방어력, 최소 데미지 보정, 치명타, 속성 상성, 버프·디버프, 캐릭터 레벨·경험치.
- 데미지 값을 가지는 대상: 기본공격 타수별 3개, 공격 신성별 각 1개, 적 유형별 공격 각 1개, 보스 패턴별 각 1개. 값은 전부 미정 (09에서 확정)
- 성장은 신성 강화(신성 데미지 상승)와 기본공격 성장 두 가지뿐이다. 기본공격 성장 경로는 미정 (06_아이템·보상에서 결정)

## 7. 체력과 사망 처리

| 항목 | 플레이어 | 적 |
|---|---|---|
| HP 필드 | MaxHp, CurrentHp. 값 미정 (09) | 유형별 MaxHp, CurrentHp. 값 미정 (09) |
| HP 감소 조건 | 적 공격 판정 적중, 무적 시간이 아닐 때 | 플레이어 공격 판정 적중 |
| HP 회복 조건 | 제단 상호작용 시 완전 회복. 횟수 제한형 회복 수단 사용 시 회복 | 없음 |
| HP 0 이하 | Dead 전환, Dead 애니메이션 재생 | Dead 전환, Dead 애니메이션 재생 |
| 사망 후 판정 | 판정 대상에서 제외 | 판정 대상에서 제외. 추가 데미지 없음 |
| 사망 후 처리 | 모든 플레이 입력 무시, 체크포인트 부활 (01_핵심 플레이 루프 9절) | 모든 AI 행동 정지, 자원 1회 지급 후 오브젝트 제거 |

회복 수단은 둘이다. 전투 중 자연 회복은 없다.

- **제단(체크포인트 거점)**: 상호작용하면 HP를 최대치로 회복한다. 제단 휴식 시 적 리스폰 여부는 미정 (05_맵·진행에서 결정)
- **횟수 제한형 회복 수단**: 사용 횟수가 제한되고 제단에서 충전된다. 형태(공용 신성인지 아이템인지), 사용 횟수, 회복량, 사용 동작은 미정 (06_아이템·보상에서 결정)

## 8. 피격 처리

이 게임은 **피격 경직(히트스턴)을 두지 않는다.** 피격은 상태 전환 없이 처리한다. 조작이 끊기지 않게 하기 위함이다.

| 항목 | 플레이어 | 적 |
|---|---|---|
| 피격 조건 | 공격 판정 접촉, 무적 시간이 아님, Dead 아님 | 공격 판정 접촉, Dead 아님 |
| 상태 전환·경직 | 없음. 현재 상태를 유지한다 | 없음. AI 상태를 유지한다 |
| 넉백·방향 | 있음. 공격이 온 방향의 반대로 가벼운 넉백 | 공격이 온 방향의 반대. KnockbackImmune이 false인 적만 적용 |
| 넉백 거리·시간 | KnockbackDistance, KnockbackDuration. 값 미정 (09) | 유형별. 값 미정 (09) |
| 무적 시간 | HitInvincibleTime. 값 미정 (09) | 없음 |
| 중복 피격 방지 | 무적 시간으로 차단 | 하나의 판정당 대상별 1회만 적용 |
| 연출 | 피격 연출(플래시 등)과 무적 중 연출(깜빡임 등). 형식 미정 (07 또는 아트) | 피격 연출만. 형식 미정 (07 또는 아트) |

플레이어 피격 처리 흐름:

1. 적 공격 판정이 플레이어에 접촉한다. 무적 시간 진행 중이면 처리를 중단한다.
2. CurrentHp에서 해당 공격의 고정 데미지를 빼고, 공격이 온 방향의 반대로 넉백을 적용한다.
3. 피격 연출을 재생하고 HitInvincibleTime 동안 무적을 적용한다.
4. CurrentHp가 0 이하면 Dead로 전환한다.

KnockbackImmune이 true인 적(일부 대형 적)과 보스는 넉백을 적용하지 않고 데미지만 적용한다. 유형·개체별 지정은 09_데이터 테이블에서 한다.

|---|---|---|---|---|---|---|---|
| Idle | 가능 | 가능 | 가능 | 가능 | 가능 | 가능 | 가능 |
| Move | 가능 | 가능 | 가능 | 가능 | 가능 | 가능 | 가능 |
| Jump(공중) | 가능 | 더블점프 보유 시 1회 | 가능 | 가능 | 가능 | 가능 | 불가능 |
| Dash | 불가능 | 불가능 | 불가능 | 불가능 | 불가능 | 불가능 | 불가능 |
| Attack | 가능 | 미정 (사용자 확인 필요) | 콤보 연결 입력 | 미정 (사용자 확인 필요) | 미정 (사용자 확인 필요) | 불가능 | 불가능 |
| Dead | 불가능 | 불가능 | 불가능 | 불가능 | 불가능 | 불가능 | 불가능 |

| Dash | Shift 입력, 쿨타임 종료 |
| Attack | D 또는 Q/W/E/R/S 입력 |
| Dead | CurrentHp 0 이하 |

Dash 상태에서는 적을 통과한다. 전환 우선순위: Dead > Dash > Attack > Jump(공중) > Move > Idle. 피격은 이 우선순위에 관여하지 않는다.

일반 대시 규칙:

- 방향: 좌우 입력 중이면 그 방향이며 캐릭터도 그 방향을 바라본다. 입력이 없으면 바라보는 방향이다.
- 무적: 없다. 대시 중에도 적 공격 판정에 피격된다.
- 충돌: 적과의 충돌을 무시하고 통과한다. 지형 충돌은 유지한다.
- 공중 사용: 가능하다. 공중에서는 착지 전까지 **1회만** 사용할 수 있고, 착지하면 초기화된다. 쿨타임과 별개로 적용한다. (AirDashMaxCount, 기본 1. 값은 09에서 확정)

조작 보정은 둘 다 채택한다. 값은 미정 (09에서 확정)

- 입력 버퍼(선입력): 행동 불가 시점의 입력을 InputBufferTime 동안 저장하고, 가능해지면 실행한다.
- 접지 유예(코요테 타임): 지면을 벗어난 뒤 CoyoteTime 동안 지상 점프를 허용한다.

## 10. 적 AI 전투 행동

적 상태는 대기 → 감지·추적 → 공격 → 복귀 / 사망이다.

| 상태 | 행동 | 전환 조건 |
|---|---|---|
| 대기 | 정지 또는 지정 구간 순찰 | 초기 상태 |
| 감지·추적 | 플레이어 방향으로 이동 | 플레이어가 DetectRange 안에 진입 |
| 공격 | 예고 동작 후 공격 판정 생성 | 플레이어가 AttackRange 안, AttackCooldown 종료 |
| 복귀 | 초기 위치로 이동 후 대기로 전환 | 플레이어가 DetectRange를 벗어남 |
| 사망 | 모든 행동 정지, 판정 제외 | CurrentHp 0 이하 |

인식 범위 DetectRange, 공격 범위 AttackRange, 이동 속도 MoveSpeed는 유형별로 따로 둔다. 값은 전부 미정 (09에서 확정). 공격 대상이 플레이어 1인이므로 공격 우선순위 판정과 타깃 재탐색은 두지 않는다.
유형별 이동과 공격 방식은 5절 표를 따른다. 개별 적 목록, 배치, 수치는 08_스테이지 설계와 09_데이터 테이블에서 정의한다.

## 11. 보스 전투 기획

| 대상 | 페이즈 | 넉백 |
|---|---|---|
| 일반 적 | 없음 | 적용 (KnockbackImmune이 false일 때) |
| 중간보스·강적 | 없음. 페이즈 없는 강화 적으로 취급한다 | KnockbackImmune으로 개별 지정 |
| 큰 보스(지역 보스) | 있음. 체력 구간 기반 전환 | 면역 (KnockbackImmune = true) |

큰 보스 규칙:

- 등장 조건과 HP: 지역 부탁 진행 중 지정 위치 진입. 보스 HP는 BossMaxHp. 개별 조건 미정 (08), 값 미정 (09)
- 페이즈 구분·전환 조건: 체력 구간(PhaseHpThreshold) 기준. 현재 HP가 다음 페이즈의 임계값 이하로 내려간 순간 전환한다. 페이즈 수와 구간 값 미정 (08·09에서 결정)
- 패턴 목록·실행 조건: 페이즈별로 사용 가능한 패턴 목록을 따로 두고, 패턴별 쿨타임(PatternCooldown)이 끝나면 실행한다. 패턴 내용 미정 (08에서 결정)
- 예고 동작: 모든 패턴에 예고 동작을 둔다. 예고 시간 PatternWindupTime. 값 미정 (09)
- 전환 연출: 페이즈 전환 시 1회성 연출을 재생한다. 연출 중 보스는 무적이며 패턴을 실행하지 않는다
- 보스 사망 조건: CurrentHp 0 이하. 보상은 자원 지급이며, 부탁 완료 처리는 부탁(퀘스트) 시스템이 담당한다 (01_핵심 플레이 루프 4~5단계)

보스 수와 개별 패턴은 전부 미정 (08_스테이지 설계에서 개별 정의)

보스 전투 예외:

| 예외 상황 | 처리 |
|---|---|
| 보스 사망과 플레이어 사망 동시 발생 | 처리 방침 미정 (05_맵·진행에서 결정). 01_핵심 플레이 루프 10절의 "부탁 완료와 사망 동시 발생"과 같은 항목으로 다룬다 |
| 페이즈 전환 연출 중 플레이어 공격 | 보스는 무적이므로 데미지를 적용하지 않는다 |
| 한 프레임에 두 페이즈 구간을 통과하는 데미지 | 처리 방침 미정 (09_데이터 테이블 확정 후 재검토) |

## 12. 보상 연결

- 적 처치 보상과 보스 처치 보상: 자원을 지급한다. 자원 이름·종류·수량 미정 (06·09에서 결정)
- 부탁 관련 보상: 가호는 부탁 완료가 아니라 **수령 시점**에 부여된다 (00_게임 콘셉트 3-2). 완료 시에는 지역 신앙 회복과 중심 서사 진전이 이뤄진다. 모두 전투 시스템이 아니라 부탁 시스템이 처리한다 (01_핵심 플레이 루프 8절)
- 경험치: 없다. 캐릭터 레벨업을 두지 않는다.
- 지급 조건과 중복 방지: 대상이 Dead로 **처음 전환될 때** 1회만 지급한다. 보상 지급 완료 플래그를 두고, 이미 지급한 대상에게 다시 지급하지 않는다.
- 드랍 형태: 즉시 획득인지 필드 드랍 후 습득인지 미정 (06_아이템·보상에서 결정)

## 13. 전투 UI 피드백

확정된 항목만 적는다. 표시 형식과 위치는 07_UI 흐름에서 정의한다.

- 표시가 확정된 항목: 플레이어 HP, 신성 쿨타임(공격 신성 5개·이동 신성·일반 대시), 현재 발현 중인 가호, 피격 연출, 무적 중 연출. 다섯 항목 모두 형식은 미정 (07 또는 아트에서 결정)
- 미정 항목: 적 HP 표시, 보스 HP 표시, 데미지 숫자 표시, 보상 획득 표시 (06·07에서 결정). 상태 이상 표시는 두지 않는다 (상태 이상 자체가 없다)

## 16. AI 구현 요청용 프롬프트

**목적**
2D 메트로배니아의 전투 시스템을 구현한다. 근접 3연타 콤보, 긴 쿨타임의 신성, 고정 데미지, 경직 없는 피격 처리, 적 AI, 보스 페이즈를 각각 분리해 구현한다.

**환경**
Unity 6, C#, PC 단독 실행, 싱글 플레이, 2D 횡스크롤 픽셀아트.

**요구 기능**

1. 기본공격: D 입력으로 Attack 상태 전환. 3연타 콤보. 애니메이션 이벤트 시점에 전방 판정 생성. 공격 중 좌우 이동 허용. ComboResetTime 안에 재입력이 없으면 1타로 초기화.
2. 공격 신성: Q/W/E/R/S. 발현 중인 가호의 배운 신성만 사용. 소모 자원 없이 쿨타임만 검사. 가호를 전환해도 쿨타임을 초기화하지 않는다.
3. 데미지 적용: 고정 데미지형. 방어력·치명타·속성 보정 없이 공격별 Damage 값을 그대로 적용한다.
4. 피격 처리: 경직 없음. Hit 상태를 만들지 않는다. HP 감소 + 반대 방향 넉백 + HitInvincibleTime 무적 + 피격 연출로 처리한다. 공격 중 피격돼도 공격을 취소하지 않는다. KnockbackImmune이 true인 대상에는 넉백을 적용하지 않는다.
5. 일반 대시: 좌우 입력이 있으면 그 방향, 없으면 바라보는 방향. 무적 없음. 공중 사용 가능. 적과의 충돌 무시, 지형 충돌 유지.
6. 조작 보정과 상태 머신: 입력 버퍼(InputBufferTime)와 접지 유예(CoyoteTime)를 구현한다. 상태는 Idle, Move, Jump(공중), Dash, Attack, Dead 6종이며 Hit 상태를 추가하지 않는다.
7. 적 AI: 대기 → 감지·추적 → 공격 → 복귀 / 사망. 유형은 근접 보행형, 원거리형, 돌진형, 비행형 4종. 모든 공격에 예고 동작을 둔다.
8. 보스: 체력 구간 기반 페이즈 전환. 페이즈별 패턴 목록, 패턴 쿨타임, 예고 동작, 전환 시 1회성 연출.
9. 보상: 대상이 Dead로 처음 전환될 때 자원을 1회만 지급한다.

**데이터 구조**
PlayerCombatData, ComboStepData, DashData, DivinityData, EnemyData, BossData, BossPatternData, ProjectileData. 필드는 14절 표를 따른다. DivinityData는 근접·원거리를 구분하는 RangeType과 판정 시점 DivinityHitTiming을 포함한다. AttackPower와 Defense 필드를 만들지 않는다. 모든 수치는 ScriptableObject 등 외부 데이터로 분리하고 하드코딩하지 않는다.

**처리 흐름**
공격 입력 → 상태·쿨타임 검사 → Attack 전환·애니메이션 재생 → 애니메이션 이벤트로 판정 생성 → 살아 있는 대상에게 고정 데미지 적용 → HP 감소·넉백 → HP 0 이하 시 Dead 전환 → 자원 1회 지급 → 상태 복귀.

**예외 조건**

- Dead 대상은 판정에서 제외하고 추가 데미지를 적용하지 않는다. 콤보 잔여 타수도 마찬가지다.
- 하나의 판정은 대상당 1회만 데미지를 적용한다.
- 무적 시간 중에는 데미지도 넉백도 적용하지 않는다.
- 보상은 Dead 첫 전환 시 1회만 지급한다.
- 쿨타임 중 입력은 InputBufferTime 동안 저장했다가 실행한다. 가호 전환으로 신성 쿨타임을 초기화하지 않는다.
- 공중 대시는 착지 전까지 1회만 허용한다(AirDashMaxCount). 초과 입력은 무시하고 착지 시 초기화한다.
- Attack 상태 중 신성·점프 허용 여부, 보스와 플레이어 동시 사망, 한 프레임 다중 페이즈 통과, 팝업 중 적 AI·쿨타임 정지 여부, 회복 수단의 형태·횟수·회복량은 미정이다. 임의로 구현하지 말고 TODO 주석으로 남긴다.

**출력 형식**
Unity 6용 C# 스크립트. 하나의 클래스에 모두 작성하지 않는다. 입력 처리는 PlayerCombat, 데미지 적용은 DamageCalculator, 체력 관리는 Health, 피격 처리는 HitReceiver, 넉백은 KnockbackReceiver, 적 AI는 EnemyStateMachine, 보스 페이즈는 BossPhaseController로 책임을 나눈다. 데이터와 로직을 분리한다. 미정 항목은 값을 채우지 말고 TODO 주석으로 남긴다.

## 17. 테스트 기준

- 기본공격이 판정 범위 안의 적에게 고정 데미지를 적용하고, 범위 밖의 적은 받지 않는가?
- D 연속 입력이 1타→2타→3타로 연결되고, ComboResetTime이 지나면 1타로 초기화되는가?
- 공격 중 좌우 이동이 가능하고, 공격 중 피격돼도 공격이 취소되지 않는가?
- 하나의 판정이 같은 적에게 데미지를 두 번 적용하지 않는가?
- 피격 시 Hit 상태로 전환되지 않고 조작이 유지되며, 반대 방향 넉백과 무적 시간이 적용되는가?
- 무적 시간 중 추가 데미지와 넉백이 모두 차단되는가?
- KnockbackImmune인 적과 보스에게 넉백이 적용되지 않는가?
- 대시가 적을 통과하고 지형에는 막히며, 대시 중 적 공격에 피격되는가?
- 쿨타임 중 신성 입력이 무시되고, 가호를 전환해도 쿨타임이 초기화되지 않는가?
- 적 HP가 0 이하가 되면 Dead로 전환되고 판정에서 제외되며, 콤보 잔여 타수가 데미지를 주지 않는가?
- 적 사망 보상이 한 번만 지급되는가?
- 적이 감지 범위 진입 시 추적하고, 이탈 시 복귀하는가?
- 적 공격에 예고 동작이 재생된 뒤 판정이 발생하는가?
- 보스가 체력 구간에서 페이즈를 전환하고 전환 연출 중 무적인가?
- 플레이어가 Dead 상태일 때 모든 입력이 차단되는가?
- 제단 상호작용으로 HP가 최대치까지 회복되는가?
