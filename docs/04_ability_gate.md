# 04. 능력 게이트

이 문서는 가호·신성 체계와, 그 능력이 여는 능력 게이트를 정의한다. 기준 문서는 00_게임 콘셉트, 01_핵심 플레이 루프, 02_플레이어 조작, 03_전투 시스템이며 네 문서와 충돌하는 내용을 두지 않는다.
게이트의 실제 배치와 방 연결은 05_맵·진행과 08_스테이지 설계, 자원과 강화 비용은 06_아이템·보상, 화면 표시 형식은 07_UI 흐름, 모든 수치는 09_데이터 테이블에서 확정한다.

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| 게임 제목 | 미정 (가제 미정) |
| 장르 | 2D 메트로배니아 |
| 개발 엔진 / 언어 | Unity 6 / C# |
| 플랫폼 | PC (Steam 출시 목표) |
| 가호 수 | 3개 (여우·늑대·용). 프롤로그에서 세 부탁 수령과 함께 일괄 부여 |
| 종족 신성 수 | 신당 5개 × 3신 = 15개. 모두 공격 신성이며 신당 1개는 유틸을 겸한다(화영난무·빙갑·번개창) |
| 공용 신성 수 | 대표 4종 확정, 추가 종류 미정 |
| 게이트 판정 방식 | 필요 능력 보유 + 요구 스킬 레벨 N 이상 |

## 2. 문서 목적과 범위

- 목적: "어떤 능력이 어떤 길을 여는가"를 구현 가능한 조건으로 확정한다. 능력 정의(신성 목록)와 잠금 정의(게이트)를 한 문서에서 짝지어 관리한다.
- 정하는 것: 가호 발현·전환 규칙, 신성 15개와 공용 신성의 목적·발동 조건·처리 흐름·예외, 게이트 종류와 판정 규칙, 습득 경로. 정하지 않는 것: 개별 게이트의 좌표와 개수(05·08), 자원 이름과 강화 비용(06), UI 표시 형식(07), 모든 수치(09).
- 수치 표기 규칙: 확정되지 않은 값은 "값 미정 (09)"로 적는다. 방향만 정한 항목은 "(가안)"을 붙인다. 임의 값을 채우지 않는다.

## 3. 가호 시스템

### 3-1. 발현

- 보유: 프롤로그에서 세 신의 부탁을 수령할 때 세 가호가 모두 부여된다 (00_게임 콘셉트 3-2절). 이후 가호가 늘거나 줄지 않는다.
- 발현: 항상 정확히 하나의 가호가 발현 중이다. 발현 중인 가호의 신성 5개가 Q/W/E/R/S에 대응한다. Q·W = 초급 2개, E·R = 고급 2개, S = 강림 1개다 (02_플레이어 조작 5-2절). 초급 2개의 Q/W 개별 배정과 고급 2개의 E/R 개별 배정은 미정 (07_UI 흐름에서 결정).
- 발현 중이 아닌 가호의 신성은 사용할 수 없다. 키 입력을 무시한다 (03_전투 시스템 15절).

### 3-2. 가호 패시브 (가안)

발현 중인 가호의 패시브가 상시 적용된다. 발현하지 않은 가호의 패시브는 적용하지 않는다. 세 패시브는 중첩되지 않는다.

| 가호 | 속성·전투 스타일 | 패시브 효과 | 필드 | 값 |
|---|---|---|---|---|
| 여우 | 불 · 근거리(도적) | 이동 속도 증가 | MoveSpeedBonus | 값 미정 (09) |
| 늑대 | 얼음 · 중거리(전사) | 받는 피해 감소 | DamageTakenReduction | 값 미정 (09) |
| 용 | 전기 · 원거리 | 신성 쿨타임 감소 + 신성 데미지 증가 | DivinityCooldownReduction, DivinityDamageBonus | 값 미정 (09) |

패시브 효과는 가안이다. 적용 방식(고정값인지 비율인지)과 값은 09_데이터 테이블에서 확정한다.

### 3-3. 가호 전환

- 장소 제약: 없다. 언제 어디서나 전환할 수 있다. 제단 전용 기능이 아니다.
- 입력: Tab (누르는 순간)으로 전환 UI를 연다. 세 방향으로 가호 이펙트가 펼쳐지고, 방향키로 하나를 선택한다. 확정 입력과 취소 입력은 미정 (07_UI 흐름에서 결정).
- 선택 중 시간: 전환 UI가 열려 있는 동안 게임 시간 배율을 SwitchTimeScale로 낮춘다. 최대 유지 시간은 SwitchWindowMaxTime이며, 초과하면 전환을 취소하고 UI를 닫는다. 두 값 모두 미정 (09).
- 전환 쿨타임: BlessingSwitchCooldown. 수 초 수준(가안). 값 미정 (09). 쿨타임 중에는 Tab 입력을 무시한다.
- 전환 결과: 발현 가호가 바뀌고 Q/W/E/R/S가 새 가호의 신성 5개로, 가호 패시브도 함께 교체된다. 신성별 쿨타임과 남은 신력은 전환해도 초기화되지 않는다. 전환으로 쿨타임이나 신력 소모를 회피할 수 없다 (03_전투 시스템 4-2절).
- 이 규칙은 02_플레이어 조작 3절·8-1절과 00_게임 콘셉트 9절에 동일하게 반영되어 있다. 입력·UI 세부는 02_플레이어 조작 8-1절이, 시스템 규칙은 이 절이 기준이다.

## 4. 신성 체계 개요

세부 규칙(신력, 쿨타임, 상태 전환, 캔슬)은 03_전투 시스템 4-2절을 따른다. 이 절은 이 문서에서 새로 확정한 것만 적는다.

| 항목 | 내용 |
|---|---|
| 등급 | 초급 2 / 고급 2 / 강림 1. 세 신 모두 동일 |
| 신성 강화 | 스킬 레벨업. 자원을 소모해 SkillLevel을 1 올린다. 최대 레벨(MaxSkillLevel)과 비용 미정 (06·09) |
| 레벨의 효과 | ① 데미지 등 성능 상승 ② 속성 게이트 개방 조건. 초급 게이트 열쇠 3개는 레벨이 곧 통과 가능한 게이트 단계를 결정한다 |
| 신력 소모 | 신성별 DivinityCost. 값 미정 (09) |
| 쿨타임 | 신성별 DivinityCooldown. 등급 기준 방향은 03_전투 시스템 4-2절 표를 따른다 |
| 신성 ID | 명명 규칙과 ID 값은 미정 (09) |

## 5. 종족 신성 목록

각 신성을 목적 / 발동 조건 / 처리 흐름 / 예외로 분해한다 (교재 Ch.8, Ch.39). 모든 수치는 값 미정 (09)이며 이 절에 숫자를 적지 않는다.
공통 발동 조건과 공통 예외는 각 신성에서 반복하지 않는다. 공통 발동 조건은 "해당 신성을 습득했고, 그 가호가 발현 중이며, 쿨타임이 끝났고, 남은 신력이 DivinityCost 이상이며, 상태가 Idle·Move·Jump(공중)·Attack일 때"다 (02_플레이어 조작 9절). 공통 예외는 "미습득·타 가호·쿨타임 중·신력 부족·Dash·Dead 상태의 입력은 무시하고, 신력을 차감하지 않으며 쿨타임도 시작하지 않는다"다 (03_전투 시스템 15절).

### 5-1. 여우 (불 · 근거리)

#### 5-1-1. 파이어볼 (초급, Q 또는 W)

| 항목 | 내용 |
|---|---|
| 목적 | 원거리 견제 수단이자 **불 게이트의 열쇠**다. 스킬 레벨에 따라 하위 게이트에서 상위 게이트까지 순차 개방한다 |
| 발동 조건 | 공통 조건. 지상·공중 모두 가능 |
| 처리 흐름 | 1) 바라보는 방향으로 불덩이 투사체를 발사한다. 2) 투사체가 적 또는 지형에 충돌하면 그 지점에서 폭발한다. 3) 폭발 반경 안의 살아 있는 대상에게 고정 데미지를 1회 적용한다. 4) 폭발 판정은 불 속성 게이트 오브젝트에도 전달한다 |
| 관련 필드 | DivinityDamage, DivinityRange, ProjectileSpeed, ExplosionRadius, SkillLevel |
| 예외 | 폭발 하나가 같은 대상에게 데미지를 두 번 적용하지 않는다. 투사체가 아무것과도 충돌하지 않으면 Lifetime 경과 시 폭발 없이 소멸한다. 게이트 오브젝트에 닿아도 SkillLevel이 GateRequiredLevel 미만이면 게이트를 열지 않는다 (7절) |

#### 5-1-2. 화영난무(火影亂舞, 가칭) (초급, Q 또는 W · 유틸)

| 항목 | 내용 |
|---|---|
| 목적 | 위험 구간에서 강적의 뒤를 잡고 무적으로 버티며 근접 딜을 넣는 진입·생존 수단이다 |
| 발동 조건 | 공통 조건. 추가로 TeleportSearchRange 안에 살아 있는 적이 1체 이상 있어야 한다 |
| 처리 흐름 | 1) TeleportSearchRange 안의 살아 있는 적 중 MaxHp가 가장 높은 적을 대상으로 정한다. MaxHp가 같으면 플레이어와의 거리가 더 가까운 적을 대상으로 한다. 2) 대상의 뒤쪽(대상이 플레이어를 바라보는 방향의 반대) 지점으로 순간이동한다. 3) 뒤쪽에 캐릭터가 설 공간이 없으면 뒤쪽 벽에 최대한 붙는 위치로 보정한다. 4) 지속 상태에 진입한다. 지속 중 캐릭터는 기본 이동 속도로 자유롭게 이동할 수 있고, 캐릭터 주변 반경에 연속 참격 판정이 자동으로 발생하며, 플레이어는 무적이다. 5) DanceDuration이 지나거나 신력이 0이 되면 지속 상태를 종료한다 |
| 자원 소모 | 발동 시 DivinityCost, 지속 중 초당 DanceCostPerSecond. 값 미정 (09) |
| 관련 필드 | TeleportSearchRange, DanceDuration, DanceCostPerSecond, DanceSlashInterval, DanceSlashRadius, DivinityDamage |
| 예외 | 사거리 안에 살아 있는 적이 없으면 사용을 거부한다. 신력을 차감하지 않고 쿨타임도 시작하지 않으며, 대상 없음을 표시한다. 지속 중 무적이므로 데미지와 넉백을 모두 받지 않는다. 지속 중 대상이 사망해도 지속 상태는 유지된다(대상 추적형이 아니다). 연속 참격은 판정 1회당 대상별 1회만 적용한다 |

#### 5-1-3. 플레임 버스트 (고급, E 또는 R)

| 항목 | 내용 |
|---|---|
| 목적 | 전방 지상 구간을 한 번에 정리하는 광역 공격이다 |
| 발동 조건 | 공통 조건 |
| 처리 흐름 | 1) 바라보는 방향의 지면 위 지정 범위에 예고 표시를 재생한다. 2) DivinityHitTiming 시점에 불길 판정을 생성한다. 3) 범위 안의 살아 있는 대상에게 고정 데미지를 1회 적용한다 |
| 관련 필드 | DivinityDamage, BurstRangeWidth, BurstRangeHeight, DivinityHitTiming |
| 예외 | 판정은 대상별 1회만 적용한다. 시전 중 이동 허용 여부는 CastMoveAllowed로 지정하며 값 미정 (09) |

#### 5-1-4. 메테오 (고급, E 또는 R)

| 항목 | 내용 |
|---|---|
| 목적 | 캐릭터 주변 전후방을 동시에 정리한다. 좌우가 함께 막힌 상황에서 쓰는 광역 공격이다 |
| 발동 조건 | 공통 조건 |
| 처리 흐름 | 1) 캐릭터를 중심으로 좌우 MeteorRange 범위를 대상 구역으로 잡는다. 2) 구역 안에 낙하 예고 표시를 재생한다. 3) 운석이 순차 낙하하며 낙하 지점마다 판정을 생성하고 고정 데미지를 적용한다 |
| 관련 필드 | DivinityDamage, MeteorRange, MeteorCount, MeteorInterval |
| 예외 | 운석 하나의 판정은 대상별 1회만 적용한다. 서로 다른 운석의 판정은 각각 적용한다. 낙하 도중 대상이 사망하면 이후 운석은 그 대상에게 데미지를 적용하지 않는다 |

#### 5-1-5. 강림-여우 (강림, S)

| 항목 | 내용 |
|---|---|
| 목적 | 위기 상황과 보스전에서 쓰는 최종 수단이다. 광역 정리와 일시적 강화를 함께 제공한다 |
| 발동 조건 | 공통 조건. 습득 조건은 8절 참조 |
| 처리 흐름 | 1) 화면 전체를 대상으로 하는 공격 연출을 재생하고 판정을 1회 생성한다. 2) 여우신이 강림해 캐릭터에 빙의·변신한다. 3) DescentDuration(약 20초, 가안) 동안 강화 상태를 유지한다. 4) 지속 시간이 끝나면 변신을 해제하고 원래 상태로 돌아간다 |
| 강화 내용 | 미정 (09). 강화 대상(데미지·쿨타임·신력 소모 중 무엇인지)과 배율을 정하지 않았다 |
| 관련 필드 | DivinityDamage, DescentDuration, DescentBuffType, DescentBuffValue |
| 예외 | 지속 중 강림 신성을 다시 입력해도 재발동하지 않고 지속 시간도 연장하지 않는다. 지속 중 가호를 전환하면 강화 상태를 즉시 종료한다 (9절). 화면 전체 판정은 대상별 1회만 적용한다 |

### 5-2. 늑대 (얼음 · 중거리)

#### 5-2-1. 프로스트 슬래시 (초급, Q 또는 W)

| 항목 | 내용 |
|---|---|
| 목적 | 중거리 견제 수단이자 **얼음 게이트의 열쇠**다. 물줄기와 폭포를 얼려 발판과 길을 만든다 |
| 발동 조건 | 공통 조건. 지상·공중 모두 가능 |
| 처리 흐름 | 1) 바라보는 방향으로 얼음 토네이도 투사체를 발사한다. 2) 투사체는 적을 관통할지 여부(ProjectilePierce)에 따라 처리하며 값 미정 (09). 3) 적중한 살아 있는 대상에게 고정 데미지를 적용한다. 4) 얼음 속성 게이트 오브젝트에 접촉하면 개방 판정을 전달한다 |
| 관련 필드 | DivinityDamage, DivinityRange, ProjectileSpeed, ProjectilePierce, SkillLevel |
| 예외 | 하나의 투사체는 같은 대상에게 데미지를 두 번 적용하지 않는다. SkillLevel이 GateRequiredLevel 미만이면 게이트를 열지 않고 통과 불가 피드백만 표시한다 (7절). 생성된 얼음 발판의 지속 시간은 미정 (05·09) |

#### 5-2-2. 아이스 차지 (초급, Q 또는 W)

| 항목 | 내용 |
|---|---|
| 목적 | 근접 확정 딜 수단이다. 적을 빙결시키고 연계 참격으로 한 번에 큰 데미지를 넣는다 |
| 발동 조건 | 공통 조건 |
| 처리 흐름 | 1) 전방에 냉기 일격 판정을 1회 생성한다. 2) 적중하지 않으면 여기서 종료한다. 3) 적중하면 대상을 빙결 상태로 만들고, 자동 연계 3연 참격(위→아래, 아래→위, 옆 순서)을 순차 실행한다. 4) 참격마다 고정 데미지를 적용한다. 5) 마지막 참격과 동시에 빙결을 해제한다 |
| 빙결 | 연출 시간 동안만 지속하는 내장형이다. 별도 상태 이상 시스템을 두지 않는다 (03_전투 시스템 13절). 보스에게도 적용한다 |
| 관련 필드 | DivinityDamage, ChargeHitRange, FreezeDuration, ComboSlashCount(3), ComboSlashInterval |
| 예외 | 미적중 시 연계 참격을 실행하지 않는다. 이때 신력과 쿨타임은 이미 소모된 상태로 둔다(입력 성립 시점에 소모하므로 되돌리지 않는다). 연계 중 대상이 사망하면 남은 참격의 판정은 생성하되 데미지를 적용하지 않는다. 빙결 중 대상은 이동과 공격을 중단하며, 빙결 시간은 FreezeDuration을 넘기지 않는다 |

#### 5-2-3. 빙갑 (고급, E 또는 R · 유틸)

| 항목 | 내용 |

| 목적 | 적 공격을 막고 되돌리는 방어형 유틸이다. 예고된 큰 공격을 정면으로 받아내는 데 쓴다 |

## 6. 공용 신성 (이동 신성)

- 성격: 종족(신)에 속하지 않는다. 가호를 어느 것으로 발현해도 사용할 수 있다.
- 습득: 신전 수업이 아니라 모험 중 획득한다. 획득 위치와 시점은 미정 (05·08).
- 키: A, Z, X, C 4개. 이동 신성 1종당 키 1개다. 어느 신성이 어느 키인지는 미정 (07 또는 09).
- 상태 조건: 02_플레이어 조작 9절 표를 따른다. Idle·Move·Jump(공중)·Attack에서 사용 가능하고 Dash·Dead에서 불가능하다.

| 이동 신성 | 목적 | 발동 조건 | 처리 흐름 | 예외 |
|---|---|---|---|---|
| 체공 | 긴 공백 구간과 활강 구간을 건넌다 | 습득 보유, 공중 상태, 남은 공중 사용 횟수 1 이상 | 키를 누르고 있는 동안 약 1초(가안) 공중에 머문다. 체공 중 미세한 좌우 이동을 허용한다. 키를 떼거나 HoverDuration이 지나면 하강한다 | 공중 사용 횟수(HoverAirUseCount) 미정 (09). 착지 시 횟수를 초기화한다. 지상에서 입력하면 무시한다 |
| 벽 붙기 | 벽면 루트를 오르내린다 | 습득 보유, 벽면에 접촉 중 | 벽에 붙어 미끄러짐 속도를 낮춘다. 벽에서 점프할 수 있다 | 발동 방식(키 입력인지 자동인지) 미정. 벽 점프 허용 여부와 미끄러짐 속도 미정 (09) |
| 신성 대시 | 일반 대시로 닿지 않는 거리를 건넌다 | 습득 보유, 쿨타임 종료 | 바라보는 방향(좌우 입력이 있으면 그 방향)으로 마법 대시한다 | 일반 대시와 별개 능력이며 쿨타임도 별개로 관리한다. 거리·지속 시간·무적 여부·공중 사용 횟수 미정 (09) |
| 비행 | 최후반 구역을 자유 이동한다 | 습득 보유(최후반 해금), 남은 신력이 FlightCostPerSecond 이상 | 지속 중 자유 비행한다. 초당 FlightCostPerSecond만큼 신력을 소모하고, 신력이 소진되면 비행을 종료하고 하강시킨다 | 하강 중 조작 처리 미정 (02_플레이어 조작 12절과 함께 09에서 확정). 소모량 미정 |

- 신력 소모: 비행은 지속 소모형으로 확정한다. 체공·벽 붙기·신성 대시의 신력 소모 여부는 미정 (09). 위 4종 외 추가 종류는 미정 (05·08의 게이트 요구가 확정된 뒤 판단).
- 더블점프는 이동 신성이 아니다. 신성 체계 밖의 해금형 기본 이동 능력이며 모험 중 획득한다 (02_플레이어 조작 4-3절).

## 7. 능력 게이트

### 7-1. 판정 모델

게이트는 두 조건을 함께 요구한다.

1. 필요 능력 보유: RequiredAbilityId를 플레이어 보유 능력 목록에서 찾는다.
2. 요구 수준 충족: 속성 게이트는 해당 신성의 SkillLevel이 GateRequiredLevel 이상이어야 한다. 이동 게이트는 보유 여부만 본다(GateRequiredLevel = 0).

속성 게이트 3종은 각각 하위·상위 2단계다. 상위 게이트는 하위보다 높은 GateRequiredLevel을 요구한다. 레벨 값은 전부 미정 (09).

### 7-2. 게이트 종류 표

| 게이트 | 단계 | 형태 | 열쇠 능력 | 요구 수준 | 통과 불가 피드백 |
|---|---|---|---|---|---|
| 불 게이트 | 하위 | 태울 수 있는 벽·덩굴 | 파이어볼 | SkillLevel ≥ 값 미정 (09) | 불 속성 아이콘과 부족 표시 |
| 불 게이트 | 상위 | 더 두꺼운 태울 수 있는 벽 | 파이어볼 | 하위보다 높은 레벨. 값 미정 (09) | 불 속성 아이콘 + 현재 레벨 / 요구 레벨 표시 |
| 얼음 게이트 | 하위 | 물줄기 (얼리면 발판 생성) | 프로스트 슬래시 | SkillLevel ≥ 값 미정 (09) | 얼음 속성 아이콘과 부족 표시 |
| 얼음 게이트 | 상위 | 폭포 (얼리면 길 생성) | 프로스트 슬래시 | 하위보다 높은 레벨. 값 미정 (09) | 얼음 속성 아이콘 + 현재 레벨 / 요구 레벨 표시 |
| 전기 게이트 | 하위 | 꺼진 회로 | 라이트닝 | SkillLevel ≥ 값 미정 (09) | 전기 속성 아이콘과 부족 표시 |
| 전기 게이트 | 상위 | 꺼진 대형 장치 | 라이트닝 | 하위보다 높은 레벨. 값 미정 (09) | 전기 속성 아이콘 + 현재 레벨 / 요구 레벨 표시 |
| 이동 게이트 | — | 높은 단차 | 더블점프 | 보유 | 도달 실패로만 표현. 별도 실패 연출은 두지 않는다 |
| 이동 게이트 | — | 벽면 루트 | 벽 붙기 | 보유 | 도달 실패로만 표현 |
| 이동 게이트 | — | 긴 공백·활강 구간 | 체공 또는 신성 대시 | 보유 | 도달 실패로만 표현 |
| 이동 게이트 | — | 최후반 구역 | 비행 | 보유 | 진입 차단 표시 |

이동 게이트 중 "긴 공백·활강 구간"에 체공과 신성 대시 중 어느 것을 요구할지는 구간마다 따로 지정한다. 구간별 지정은 08_스테이지 설계에서 한다.

### 7-3. 배치 원칙

- 각 마을의 메인 동선은 **그 마을 신의 속성 게이트와 공용 능력(이동 신성·더블점프)만** 열쇠로 쓴다. 세 마을을 어느 순서로 공략해도 진행이 성립해야 하기 때문이다 (00_게임 콘셉트 4-1절).
- 타 속성 게이트는 마을 간 교차 잠금에 쓴다. 대상은 보상 구역과 역주행 동선이며, 메인 동선에 두지 않는다.
- 상위 속성 게이트는 그 신의 초급 신성을 여러 번 강화한 뒤에야 열린다. 따라서 상위 게이트 뒤는 보상 구역이거나 후반 동선이다. 구체 배치, 게이트 개수, 방 연결은 05_맵·진행과 08_스테이지 설계에서 정의한다.

### 7-4. 판정 처리 흐름

1. 플레이어가 게이트에 접촉하거나 열쇠 능력의 판정이 게이트 오브젝트에 전달된다.
2. 게이트의 RequiredAbilityId를 플레이어 보유 능력 목록과 대조한다.
3. 미보유면 통과를 막고 부족한 능력을 표시한다. 처리를 종료한다.
4. 보유하면 속성 게이트인 경우 해당 신성의 SkillLevel과 GateRequiredLevel을 비교한다.
5. 레벨이 부족하면 통과를 막고, 현재 레벨과 요구 레벨을 함께 표시한다.
6. 두 조건을 모두 만족하면 게이트를 개방 상태로 바꾸고 통과를 허용한다.
7. 개방 상태를 저장한다. 개방된 게이트는 다시 판정하지 않는다.

### 7-5. 피드백 규칙

- 통과 불가 시 "무엇이 부족한지"를 표시한다. 부족 항목은 능력 미보유와 레벨 미달 두 가지로 구분한다.
- 통과하지 못한 게이트의 위치를 지도에 기록한다 (01_핵심 플레이 루프 4절 3단계). 표시 형식과 위치는 07_UI 흐름에서 정의한다. 이 문서는 표시할 내용만 고정한다.

## 8. 습득 경로 정리

| 능력 | 습득 경로 | 조건 |
|---|---|---|
| 가호 3종 | 프롤로그에서 세 부탁 수령 시 일괄 부여 | 없음. 1회 처리 |
| 종족 초급 신성 (6개) | 신전 수업 | 해당 신의 가호 보유 + 수업 해금(스토리 진행도) |

| 종족 강림 신성 (3개) | 습득 난이도가 높다 | 습득 조건 미정 (06·08에서 결정). 임의로 정하지 않는다 |

- 수업은 자원만 모으면 아무 때나 들을 수 있는 구조가 아니다. 스토리 진행도가 부족하면 자원이 충분해도 습득을 허용하지 않는다 (01_핵심 플레이 루프 10절). 신성 강화는 습득과 별개 처리이며, 습득하지 않은 신성은 강화할 수 없다.

## 11. AI 구현 요청용 프롬프트

**목적**
가호 발현·전환 시스템, 신성 15개와 공용 이동 신성, 스킬 레벨 기반 능력 게이트 판정을 구현한다. 검증 대상은 "능력을 얻거나 강화하면 이전에 막혀 있던 게이트가 열린다"는 흐름이다.

**환경**
Unity 6, C#, PC 단독 실행, 싱글 플레이, 2D 횡스크롤 픽셀아트. 입력은 행동 이름으로 참조하며 키 코드를 직접 참조하지 않는다.

**요구 기능**

1. 가호 관리: 세 가호를 보유 상태로 두고 항상 하나만 발현시킨다. 발현 가호의 신성 5개를 Q/W/E/R/S에 매핑하고 가호 패시브를 적용한다.
2. 가호 전환: Tab으로 전환 UI를 연다. UI 표시 중 게임 시간 배율을 SwitchTimeScale로 낮추고, 방향키로 세 가호 중 하나를 선택한다. 전환 후 BlessingSwitchCooldown을 시작한다. 전환해도 신성 쿨타임과 남은 신력을 초기화하지 않는다.
3. 신성 실행: 신성별 처리를 개별 클래스로 분리한다. 투사체형(파이어볼, 프로스트 슬래시, 라이트닝, 번개창), 지속형(화영난무, 블리자드, 브레스, 강림 3종), 채널링형(번개 광선), 연계형(아이스 차지), 흡수·반사형(빙갑), 즉발 광역형(플레임 버스트, 메테오)으로 유형을 나눈다.
4. 스킬 레벨: 신성마다 SkillLevel을 두고 자원 소모로 1씩 올린다. SkillLevel은 데미지 등 성능과 게이트 개방 조건 양쪽에 연결한다.
5. 게이트 판정: RequiredAbilityId 보유 여부와 SkillLevel ≥ GateRequiredLevel을 함께 검사한다. 두 조건을 모두 만족할 때만 개방하고, 개방 상태를 저장한다.
6. 공용 이동 신성: 체공, 벽 붙기, 신성 대시, 비행. 습득 여부·쿨타임·신력 검사 구조를 만든다. 비행만 지속 소모형으로 구현하고, 나머지의 소모 여부는 데이터로 받는다.
7. 통과 불가 피드백: 능력 미보유와 레벨 미달을 구분해 표시 요청을 보낸다.

**데이터 구조**
BlessingData, BlessingSwitchData, DivinityData, DivinityEffectData, MoveDivinityData, GateData, DivinityAcquireData. 필드는 10절 표를 따른다. 03_전투 시스템 14절의 DivinityData 필드를 유지한 채 SkillLevel, MaxSkillLevel, GateKeyType을 추가한다. 모든 수치는 ScriptableObject 등 외부 데이터로 분리하고 하드코딩하지 않는다. AttackPower와 Defense 필드는 만들지 않는다(고정 데미지형).

**처리 흐름**
입력 → 발현 가호·습득 여부·쿨타임·신력 검사 → 신성 실행 → 판정 생성 → 고정 데미지 적용 → (속성 신성인 경우) 게이트 오브젝트에 개방 판정 전달 → 게이트가 RequiredAbilityId와 GateRequiredLevel을 검사 → 두 조건 충족 시 개방·저장, 미충족 시 차단·피드백.

**예외 조건**

- 화영난무는 사거리 안에 살아 있는 적이 없으면 발동하지 않고 신력과 쿨타임을 소모하지 않는다. 지속 중에도 게이트 판정은 평소대로 수행한다. 무적이 게이트 통과 조건을 대체하지 않는다.
- 지속형·채널링형 신성 진행 중 가호를 전환하면 해당 효과를 즉시 종료한다. 단 번개창의 전기 장막은 지속 시간까지 유지한다.
- 번개 광선은 다음 회차 신력 소모량이 남은 신력보다 크면 즉시 종료하고 경직을 해제한다. 전기 장막은 중첩하지 않고, 재착탄 시 기존 장막을 제거하고 새로 생성한다. 빙갑의 흡수는 AbsorbCap을 넘기지 않으며 상한 도달 시 종료하고 반사 판정을 생성한다.
- 능력은 보유하나 SkillLevel이 부족하면 게이트를 열지 않고, 현재 레벨과 요구 레벨을 함께 표시한다. RequiredAbilityId가 비어 있는 게이트는 통과 불가로 처리하고 오류를 기록한다.
- 판정 중 보유 능력이나 SkillLevel이 바뀌면 판정을 다시 수행한다. 이미 개방한 게이트는 개방 처리를 반복하지 않는다. 이미 보유한 신성·이동 신성은 중복 지급하지 않고, 강림 지속 중 재입력은 무시한다.
- 강림 신성의 강화 내용, 강림 습득 조건, 벽 붙기 발동 방식, 체공 공중 사용 횟수, 비행 하강 중 조작, 구역 갇힘 처리는 미정이다. 임의로 구현하지 말고 TODO 주석으로 남긴다.

**출력 형식**
Unity 6용 C# 스크립트. 하나의 클래스에 모두 작성하지 않는다. 가호 관리는 BlessingManager, 전환 UI 제어는 BlessingSwitchController, 신성 실행은 DivinitySkill 기반 파생 클래스, 스킬 레벨은 DivinityLevelManager, 게이트 판정은 AbilityGate와 GateChecker, 이동 신성은 MoveDivinityController로 책임을 나눈다. 데이터와 로직을 분리한다. 미정 항목은 값을 채우지 말고 TODO 주석으로 남긴다.
