# 00. 게임 콘셉트

이 문서는 게임의 방향을 정의하는 기준 문서다. 이후 작성하는 모든 상세 기획서(01~09)는 이 문서의 콘셉트, 핵심 재미, 범위 정의를 기준으로 삼는다.

## 1. 게임 기본 정보

| 항목 | 내용 |
|---|---|
| 게임 제목 | 미정 (가제 미정) |
| 장르 | 2D 메트로배니아 |

## 2. 한 문장 콘셉트

이 게임은 플레이어가 몸에 깃든 동물 신의 부탁을 대리로 수행해 새로운 가호(加護)를 얻고, 그 가호로 이전에 지나갈 수 없던 길을 열어, 신전을 중심으로 하나로 이어진 현계(現界) 맵을 넓혀가는 과정을 반복하는 2D 메트로배니아다.

이 콘셉트가 가리키는 재미의 원인은 다음 하나다.
이미 한 번 지나가며 본 적 있는 막힌 길이, 새 가호를 얻은 뒤 통과 가능한 길로 바뀌는 순간이다.

이 문장은 기능 추가 판단의 기준이다. 추가하려는 기능이 "가호 해금 → 막힌 길 개방 → 맵 확장"의 반복을 강화하지 않으면 우선순위를 뒤로 미룬다.

## 3. 핵심 플레이 경험

- 플레이어가 가장 자주 하는 행동: 맵을 이동하며 미탐험 구간을 탐색한다. 진로를 막는 적을 근접 공격과 스킬로 처치한다. 통과할 수 없는 지형을 확인하고 기억한다.
- 플레이어가 달성해야 하는 목표: 신앙이 약해진 동물 신들의 부탁을 대리로 수행해 신앙을 회복시킨다.
- 플레이어가 얻는 보상: 새로운 가호(이동·전투 능력), 스킬 습득과 강화에 쓰는 자원, 열린 지도 영역.
- 플레이어가 느껴야 할 감정: 막혀 있던 길이 열릴 때의 해결감. 신전 구조가 머릿속에서 하나로 연결될 때의 파악감.
- 게임을 반복하게 만드는 이유: 새 가호를 얻을 때마다 이전에 지나친 막힌 길들이 다시 갈 수 있는 목적지 목록으로 바뀐다.

플레이어는 수인(獸人)과 신들 사이에 낀 인간이다. 플레이어의 몸 안에 세 동물 신이 깃들어 있고, 상황에 따라 그중 한 신의 가호를 발현시켜 힘을 사용한다.
동물 신은 **여우, 늑대, 용** 세 신이다. 각 신의 고유한 이름과 가호 구성은 미정이다. (04_능력 게이트에서 결정)

세계는 두 층으로 나뉜다. (지명은 모두 가칭)

- **현계(現界)**: 세 신의 신전이 중심에 있고, 신전에서 각 신을 숭배하는 마을들이 이어진다. 탐험과 모험의 무대다.
- **신계(神界)**: 세 동물 신이 존재하는 공간. 신전에서 주인공만 오갈 수 있다. 신들은 현계에 직접 내려올 수 없고, 주인공 안에 깃들어 함께 현계로 내려간다.

신계의 게임플레이 역할(휴식, 신과의 대화, 스킬 습득 장소 등)은 미정이다. (05_맵·진행에서 결정)

## 4. 핵심 재미

### 4-1. 1순위 재미 — 탐험과 가호 해금

핵심 재미 한 문장: 새 가호를 얻어 막혀 있던 길이 열리고, 어두웠던 지도가 한 칸씩 밝혀지는 재미.

이 재미를 만드는 기능 단위:

| 기능 | 역할 |
|---|---|
| 가호 획득 처리 | 신의 부탁 완료 시 가호를 플레이어에게 부여하고 보유 상태로 저장한다 |
| 능력 게이트 판정 | 지형·오브젝트마다 통과에 필요한 가호를 지정하고, 보유 여부로 통과 가능·불가를 판정한다 |
| 통과 불가 피드백 | 가호가 없어 통과하지 못했을 때 "무엇이 부족한지"를 플레이어가 알 수 있게 표시한다 |
| 자동 지도 기록 | 방문한 구간을 지도에 기록하고, 미탐험 구간과 구분해 표시한다 |
| 되돌아가기 동선 | 새 가호 획득 후 이전 구역으로 돌아가는 경로와 단축로 개방 규칙을 둔다 |
| 이동기 | 도달 가능 범위를 넓히는 이동 능력. 종류 미정 (02_플레이어 조작에서 결정) |

세부 배치 규칙과 게이트 종류는 04_능력 게이트, 05_맵·진행에서 정의한다.

### 4-2. 2순위 재미 — 성장과 전투

성장과 전투는 탐험을 위한 보조 요소다. 전투 자체를 최종 목표로 설계하지 않는다.

| 기능 | 역할 |
|---|---|
| 기본 공격 | 근접 공격. 진로를 막는 적을 제거한다 |
| 스킬 | 근접과 원거리를 모두 포함하는 혼합형. 신별 가호에 따라 구성이 달라진다 |
| 스킬 습득 | 자원을 사용해 새 스킬을 배운다 |
| 스킬 강화 | 자원을 사용해 보유 스킬의 성능을 올린다 |
| 자원 획득 | 탐험·전투로 자원을 얻는다. 자원의 이름과 종류는 미정 (06_아이템·보상에서 결정) |

스킬 습득과 스킬 강화가 이 게임의 자원 사용처다. 상점은 두지 않는다.

### 4-3. 이 재미를 방해하는 요소

- 전투 비중이 커져 탐험 시간이 밀리는 구성. 전투는 탐험 동선을 막는 장애물 수준으로 유지한다.
- 사망 시 재화 손실·시체 회수 방식. 되돌아가기 자체를 벌칙으로 만들어 탐험 의욕을 떨어뜨리므로 채택하지 않는다.
- 미저장 탐험 기록 소실 폭이 지나치게 큰 경우. 체크포인트 간격과 지도 저장 시점 규칙으로 통제한다. 세부 규칙은 미정 (05_맵·진행에서 결정)

## 5. 대상 플레이어

- 대상 플레이어: 메트로배니아 경험자와 메트로배니아 입문자 양쪽.
- 예상 경험 수준: 일반 액션 게임을 조작할 수 있는 수준.
- 선호하는 플레이 방식: 정해진 순서를 따라가기보다 맵을 직접 뒤지며 길을 찾는 방식.
- 플레이 길이: 10시간 내외의 긴 단일 플레이. 짧은 반복 세션형이 아니다.
- 난이도 방향: 보통. 일반 액션 게임 수준으로 잡는다.
- 두 층을 동시에 수용하기 위해 난이도 조절 수단을 둔다. 조절 방식(옵션 제공, 보조 아이템, 자동 보정 등)은 미정이다.

## 6. 게임의 기본 흐름

기본 흐름:

타이틀 화면 → 게임 시작(신규 또는 이어하기) → 신전 맵 탐험 → 능력 게이트 확인(통과 가능/불가 판정) → 전투 및 자원 획득 → 신의 부탁 수행 → 가호 획득 → 이전에 막혀 있던 구간으로 복귀 → 새 구역 개방 → 탐험 반복

상세 설명:

플레이어는 신전을 중심으로 마을들이 이어진 현계 맵을 탐험한다. 신전에서는 주인공만 신계를 오갈 수 있다. 이동 중 통과할 수 없는 지형을 만나면 필요한 가호가 무엇인지 확인하고 지도에 남긴 뒤 다른 경로를 찾는다.
동물 신의 부탁을 완료하면 새 가호를 얻는다. 가호를 얻으면 이전에 막혀 있던 구간이 통과 가능해지고, 플레이어는 그 지점으로 돌아가 새 구역을 연다.
탐험 중 얻은 자원은 스킬 습득과 스킬 강화에 사용한다.
사망하면 체크포인트에서 부활한다. 재화는 잃지 않는다. 대신 마지막 저장 이후의 미저장 탐험 기록(지도 기록 등)이 소실된다.

## 7. 포함할 기능 (MVP)

MVP는 "이 기능이 없으면 핵심 루프를 테스트할 수 없는가"를 기준으로 정한다.
핵심 루프는 "이동 → 막힌 길 확인 → 능력 획득 → 막힌 길 통과"다.

| 기능 | MVP 범위 | 없으면 안 되는 이유 |
|---|---|---|
| 기본 이동 | 좌우 이동, 점프 | 맵을 이동할 수 없으면 탐험 자체가 성립하지 않는다 |
| 기본 공격 | 근접 공격 1종 | 진로를 막는 적을 제거하는 최소 수단이다 |
| 이동기 1종 | 종류 미정 (02_플레이어 조작에서 결정) | 능력으로 도달 범위가 넓어지는 구조를 검증하는 최소 능력이다 |
| 한 종족(신)의 스킬 세트 | 여우·늑대·용 중 어느 신인지 미정 (04_능력 게이트에서 결정) | 가호별로 힘이 달라지는 구조를 검증하는 최소 단위다 |

MVP에서 검증할 질문: "새 능력을 얻은 뒤 이전에 막혀 있던 길을 통과하는 흐름이 재미있는가?"
이 흐름이 성립하지 않으면 기능을 더 추가해도 문제는 해결되지 않는다.

MVP에는 포함하지 않지만 본편에는 필요한 기능(구현 순서는 이후 문서에서 정한다):
자원 획득, 스킬 습득, 스킬 강화, 체크포인트 부활, 지도 기록·저장, 다수의 동물 신과 가호, 난이도 조절.

## 8. 제외할 기능

아래 기능은 이 프로젝트에서 구현하지 않는다. 확장 검토 대상이 아니라 확정 제외다.

| 제외 기능 | 사유 |
|---|---|
| 장비 강화 | 성장 축을 스킬 습득·강화 하나로 유지한다. 자원 사용처가 나뉘면 탐험 보상의 의미가 흐려진다 |
| 퀘스트 분기 | 신의 부탁은 가호 획득 경로이며, 분기 선택 구조를 두지 않는다 |
| 상점 | 스킬 습득·스킬 강화가 자원 사용처 역할을 대신한다 |
| 멀티플레이 | 싱글 플레이로 확정했다 |

사망 시 재화 손실과 시체 회수 방식도 채택하지 않는다. (4-3 참조)

## 9. 주요 시스템 요약

각 시스템은 확정된 콘셉트에서 도출되는 범위까지만 적는다. 세부 규칙은 각 상세 문서에서 정의한다.

| 시스템 | 한 문장 요약 | 상세 문서 |
|---|---|---|
| 플레이어 조작 시스템 | 좌우 이동, 점프, 이동기 입력을 처리한다. 이동기 종류는 미정 | 02_플레이어 조작 |
| 전투 시스템 | 근접 기본 공격과 근·원거리 혼합 스킬의 입력·판정·데미지·사망을 처리한다 | 03_전투 시스템 |
| 가호 시스템 | 플레이어가 보유한 신의 가호를 관리하고, 상황에 따라 하나의 가호를 발현시킨다 | 04_능력 게이트 |
| 능력 게이트 시스템 | 지형·오브젝트별 필요 가호를 판정해 통과 가능 여부를 결정한다 | 04_능력 게이트 |
| 맵·진행 시스템 | 신전 중심의 현계 맵 구역 연결, 신계 출입(신전에서만 가능), 지도 기록, 체크포인트, 부활을 관리한다 | 05_맵·진행 |
| 보상·자원 시스템 | 탐험과 전투로 얻는 자원의 지급 조건과 수량을 관리한다. 자원 종류는 미정 | 06_아이템·보상 |
| 성장 시스템 | 자원을 소비해 스킬을 습득하고 강화한다 | 06_아이템·보상 |
| 적 AI 시스템 | 적의 감지, 이동, 공격 조건을 처리한다. 세부는 미정 | 03_전투 시스템 |
| 저장 시스템 | 가호 보유 상태, 스킬 상태, 지도 기록, 체크포인트 위치를 저장한다. 저장 시점 규칙은 미정 | 05_맵·진행 |
| UI 시스템 | HUD, 지도, 스킬 화면의 표시와 갱신을 담당한다 | 07_UI 흐름 |

## 10. 화면 구성 요약

콘셉트에서 필요성이 확정되는 화면만 적는다. 각 화면의 표시 데이터와 전환 조건은 07_UI 흐름에서 정의한다.

| 화면 | 필요성의 근거 | 표시할 내용 |
|---|---|---|
| 타이틀 화면 | 신규 시작과 이어하기 진입점이 필요하다 | 미정 |
| 인게임 HUD | 전투와 가호 상태를 플레이 중 확인해야 한다 | 체력, 현재 발현 중인 가호, 스킬 상태 (세부 미정) |
| 지도 화면 | 탐험이 1순위 재미이며, 밝혀진 구간과 미탐험 구간을 구분해 보여줘야 한다 | 방문 구간, 미탐험 구간, 통과하지 못한 게이트 위치 (세부 미정) |
| 스킬 화면 | 스킬 습득·강화가 유일한 자원 사용처다 | 보유 스킬, 보유 자원, 습득·강화 비용 (세부 미정) |
| 설정 화면 | PC 상용 출시 기준으로 키 설정과 옵션이 필요하다 | 미정 |

상점 화면은 두지 않는다. 인벤토리 화면의 필요 여부는 아이템 구조가 정해진 뒤 판단한다. (06_아이템·보상에서 결정)

## 11. 아트와 분위기 방향

- 전체 분위기: '동물신 신전'의 신비로움. 세 동물 신(여우, 늑대, 용)을 숭배하는 세상을 배경으로 한다.
- 참고 분위기: 메이플스토리 '시간의 신전'. 참고 대상은 분위기이며 시스템을 옮겨오지 않는다.
- 아트 스타일: 픽셀아트.
- 캐릭터 스타일: 주인공은 수인과 신들 사이에 낀 인간. 몸 안에 동물 신이 깃든 설정이 외형에 드러나야 한다. 세부 디자인은 미정.
- 등장 존재: 오리, 도깨비불 같은 신비로운 존재들이 사는 세계로 구성한다. 그 외 종류는 미정.
- UI 스타일: 미정.
- 색감: 미정.
- 연출 방향: 가호 획득과 게이트 개방 순간을 플레이어가 놓치지 않도록 연출한다. 구체적 연출 방식은 미정.

## 12. 개발 범위 요약

| 항목 | 내용 |
|---|---|
| 목표 버전 | 상용 출시 버전 (Steam) |
| 구현 기간 목표 | 2~3년, 1인 개발 |
| 총 분량 목표 | 플레이 시간 10시간 내외 |
| 핵심 완성 기준 | 가호 해금으로 막힌 길이 열리고 맵이 확장되는 루프가 게임 전체에 걸쳐 이어진다 |
| MVP 완성 기준 | 기본 이동, 근접 기본 공격, 이동기 1종, 한 신의 스킬 세트로 "능력 획득 → 막힌 길 통과"를 1회 이상 실행할 수 있다 |

## 13. AI 구현 요청용 콘셉트 요약

**목적**
2D 메트로배니아의 핵심 루프를 검증할 MVP를 만든다. 검증 대상은 "새 능력을 얻어 이전에 막혀 있던 길을 통과하는" 흐름이다.

**환경**
Unity 6, C#, PC 단독 실행, 싱글 플레이, 픽셀아트 2D.

**요구 기능 (MVP)**
1. 플레이어 기본 이동: 좌우 이동, 점프.
2. 근접 기본 공격 1종.
3. 이동기 1종. 종류는 미정이므로 능력 보유 여부로 사용 가능·불가가 갈리는 구조만 먼저 만든다.
4. 한 동물 신의 스킬 세트. 어느 신인지 미정. 근접과 원거리를 모두 포함하는 혼합형으로 구성한다.
5. 능력 게이트: 통과에 필요한 능력을 지정할 수 있는 지형·오브젝트.

**데이터 구조**
- 플레이어 보유 능력 목록 (능력 ID 집합)
- 능력 정의 (능력 ID, 표시 이름, 소속 신) — 소속 신은 여우·늑대·용 중 하나. 고유한 이름은 미정
- 능력 게이트 정의 (게이트 ID, 필요 능력 ID, 위치)
- 스킬 정의 (스킬 ID, 사거리 구분, 소모 자원, 쿨타임) — 모든 수치 미정
- 구체 수치는 09_데이터 테이블에서 확정한다. 임의 값으로 채우지 않는다.

**처리 흐름**
1. 플레이어가 게이트에 접촉한다.
2. 게이트의 필요 능력 ID를 플레이어 보유 능력 목록과 대조한다.
3. 보유하면 통과를 허용한다.
4. 미보유면 통과를 막고, 부족한 능력을 알리는 피드백을 표시한다.
5. 능력을 획득하면 보유 능력 목록에 추가하고 저장한다.

**예외 조건**
- 이미 보유한 능력을 다시 획득하면 중복 추가하지 않는다.
- 필요 능력 ID가 정의되지 않은 게이트는 통과 불가로 처리하고 오류를 기록한다.
- 사망 상태에서 들어온 이동·공격 입력은 무시한다.
- 사망 시 체크포인트에서 부활한다. 재화는 차감하지 않는다. 미저장 탐험 기록은 소실된다.
- 게이트 통과 판정 중 능력이 변경되면 판정을 다시 수행한다.

**출력 형식**
Unity 6용 C# 스크립트. 데이터·로직·UI의 책임을 분리한다. 수치는 코드에 하드코딩하지 말고 외부 데이터로 분리한다. 미정 항목은 값을 채우지 말고 TODO 주석으로 남긴다.

## 14. 검토 체크리스트

- 게임을 한 문장으로 설명할 수 있는가?

- 핵심 재미가 구체적으로 작성되어 있는가?
- 포함할 기능과 제외할 기능이 구분되어 있는가?
- 핵심 플레이 루프가 보이는가?
- 주요 시스템이 구현 가능한 단위로 정리되어 있는가?
- 화면 구성이 게임 흐름과 연결되어 있는가?
- MVP 범위가 너무 크지 않은가?
- AI에게 전달할 수 있는 콘셉트 요약이 있는가?
