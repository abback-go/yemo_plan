# 07. 구조 정리·최적화 (2026-10-04)

> 사용자 요청: 앞으로 기능·스토리·진행이 아주 많이 바뀔 것을 생각해 코드를 게임 프로그래밍 패턴으로 정리하고, 고치기 쉽게 문서로 남기고, 퀄리티는 비슷하게 유지하며 불필요한 연산을 줄인다.
> 사용자 결정: 중간 깊이(동작 그대로, 데이터 분리·패턴 정리·거대 파일 분할) · 대본은 GDScript 유지+정리 · 저장 호환은 깨져도 됨 · 서브에이전트 사용.

## 1. 어떻게 했나
1. **감사**(읽기 전용 4명): 적·전투 / 월드·배경 / 대본·UI·코어 / 세라·인물·시험 → 파일:줄 근거가 있는 보고서.
2. **기준 만들기**: 시험 실행기에 난수 고정(`seed`), 시간 효과를 프레임 기준으로(`Fx.now_ms`, `FRAME_CLOCK=1`), 일괄 회귀 `regress.sh`, 스크린샷 비교 `imgdiff.py`. → 같은 코드면 결과가 픽셀까지 같다.
3. **영역별 정리**(5명, 각자 작업 사본, 파일 소유권으로 충돌 방지): 대본·진행 / 배경 / 월드·소품·생성기 / 적·효과 / 세라·인물.
4. **통합**: 겹친 파일은 시험 실행기 하나(자동 병합). 영역 간 요청 6건 반영. 리팩터 전후 비교로 동작 동일 확인.

## 2. 바뀐 것 (요약)
- **장 = 모듈**: 1장도 확장(`ch1`)으로. 장 정보(제목·꼬리·지역·전이진·크레디트)는 `data_<장>.gd`의 `CHAPTER` 한 곳. 대본은 장면별 36개 파일(`story/<장>/*.gd`), 시험용은 `story/dev/`. 대본 ID 색인·중복 검사.
- **데이터·규칙 하나로**: 조건식 `Cond`, 보상 `Rewards`, 수업 해금 판정을 UI에서 `Quests`로, 소품 kind 표(`PROPS`), 공격 종류 묶음(`core/hit.gd`), 세라 수치(`tuning.tres`)·문구(`PlayerText`).
- **패턴**: 세라 파사드 + 컴포넌트(Motor·Caster·Gauge·Health), 적 `StateClock`·`BossKit`·`TelegraphHazard`·EnemyBase 도우미, 입자 풀·그라디언트 캐시, 플래그 신호(`flag_changed`), 방 색인 자동 생성(`world/rooms/_index.gd`).
- **도구**: `tools/story_lint.py`(없는 대본 ID·플래그), `roomgen.py validate`, CI 정적 검사(생성물 동기화·도달·컴파일).
- **문서**: `docs/dev/README.md`(입구) + 영역별 6개.

## 3. 성능 (측정 — 클라우드 리눅스, 소프트웨어 GL, 다른 작업과 CPU를 나눠 쓴 상태라 절대값보다 비율)
| 항목 | 전 | 후 |
|---|---|---|
| 시장(k_market) 소품 그리기 명령/프레임 | 약 885 | 35~77 |
| 시장 배경 그리기 시간/프레임 | 약 1.3~5ms | 0.3~0.5ms |
| 신전 기록실 그리기 호출/프레임 | 5,207 | 718 (정적 배경 텍스처 굽기) |
| 신전 기록실 프레임 | 7fps | 15~19fps (같은 환경) |
| 적 그림 다시 그리기(120프레임) | 2,640 | 600 |
| 새로 만든 입자 노드 | 796 | 52 |
| 미니맵 첫 표시 | 방 165개 전부 로드(약 1초 멈춤) | 색인 하나(수 ms) |
- **웹 실기기 fps는 재지 못했다** — 사용자가 태블릿·PC에서 시장·신전 서고를 다시 확인해야 한다.
