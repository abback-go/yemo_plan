## 1. 이번에 만든 것

```
game/
├─ project.godot          프로젝트 설정 (해상도, 입력 키, 렌더러)
├─ core/game_const.gd     공용 상수 (TILE = 16)
├─ player/
│  ├─ player.tscn         세라 씬 (노드 구성)
│  ├─ player.gd           세라 동작 코드
│  ├─ player_tuning.gd    조정 수치 목록 (정의)
│  └─ player_tuning.tres  조정 수치 값 (에디터에서 수정)
├─ levels/
│  ├─ test_room.tscn      테스트 방 (계단 1~4T, 대시 간격, 낮은 천장)
│  └─ test_room.gd        R키로 다시 시작
└─ ui/debug_overlay.gd    왼쪽 위 상태 표시
```

`.gd.uid` 파일은 Godot이 파일마다 붙이는 고유 번호다. 지우지 말고 함께 둔다.

## 2. 프로젝트 설정 — 에디터에서 확인하기

**Project → Project Settings**에서 아래 항목을 찾아보자.

| 항목 | 값 | 이유 |
|---|---|---|
| Display > Window > Size > Viewport Width/Height | 640 × 360 | 기준 해상도 (concept.md 11절) |
| Window Width/Height Override | 1280 × 720 | 실행 창 크기. 640×360의 2배 |
| Stretch > Mode | viewport | 640×360으로 그린 뒤 통째로 확대 → 픽셀이 반듯함 |
| Stretch > Scale Mode | integer | 2배·3배처럼 정수 배율로만 확대 → 픽셀 크기가 들쭉날쭉하지 않음 |
| Rendering > Textures > Default Texture Filter | Nearest | 확대할 때 흐리게 보간하지 않음 (픽셀아트 필수) |
| Rendering > Renderer | Compatibility | 가장 가벼운 렌더러. 사양 낮은 PC에서도 잘 돈다. 2D 게임에 충분 |

**Input Map** 탭에는 `move_left`, `jump`, `dash` 등 행동 이름과 키가 등록되어 있다. 코드는 키(Z, C)가 아니라 **행동 이름**으로 입력을 읽는다. 그래서 키를 바꿔도 코드는 고칠 필요가 없다.

## 3. 핵심 개념 7가지

### ① 씬과 노드
`player.tscn`을 더블클릭하면 왼쪽 **Scene** 패널에 이런 나무 구조가 보인다.

```
Player (CharacterBody2D)      ← 움직이는 몸. 스크립트 player.gd가 붙어 있음
├─ CollisionShape2D           ← 충돌 판정 사각형 (12×30px)
├─ Visual (Node2D)            ← 늘림·찌그러짐 연출을 거는 곳
│  └─ Flip (Node2D)           ← 좌우 반전을 거는 곳
│     ├─ Body (ColorRect)     ← 임시 몸통 (14×32px, 32px 후보)
│     └─ FacingMark           ← 바라보는 방향 표시 (눈 위치)
└─ Camera2D                   ← 세라를 따라가는 카메라
```

Godot에서 게임은 **노드**를 조립해 만든다. 노드를 묶어 저장한 것이 **씬**이고, 씬은 다른 씬 안에 넣을 수 있다. `test_room.tscn` 안에 `player.tscn`이 통째로 들어 있는 것처럼.

연출용 노드를 Visual > Flip 두 겹으로 나눈 이유: 늘림·찌그러짐(scale 변경)과 좌우 반전(scale.x = -1)이 같은 노드에서 일어나면 서로 덮어쓴다.

### ② `_physics_process(delta)`와 `move_and_slide()`
- `_physics_process`는 **1초에 60번** 호출된다. `delta`는 지난 호출 이후 흐른 시간(약 0.0167초)이다.
- 속도(`velocity`)를 정해 두고 `move_and_slide()`를 부르면 Godot이 벽·바닥과의 충돌을 처리하며 움직여 준다.
- 그래서 코드의 흐름은 **입력 읽기 → 속도 계산 → move_and_slide() → 상태 정리**다 (`player.gd`의 `_physics_process`).

### ③ 상태(State)
`enum State { IDLE, RUN, JUMP, FALL, DASH }`. 세라는 한 번에 하나의 상태에 있다. 대시 중에는 이동·중력 처리를 건너뛰는 식으로 상태에 따라 하는 일이 달라진다. 공격·피격·스킬이 추가되면 상태도 늘어난다.

### ④ 점프 공식 — '높이'와 '시간'으로 정하기
기획서는 "높이 3.5T"처럼 결과로 말한다. 코드는 이를 거꾸로 계산한다.

- 중력 `g = 2h / t²`, 점프 초속 `v = 2h / t` (h = 높이, t = 최고점까지 시간)
- 그래서 `jump_height_max_t`와 `time_to_apex` 두 값만 바꾸면 중력과 점프 힘이 자동으로 맞춰진다.
- **낮은 점프**: 올라가는 중 버튼을 떼면 상승 속도를 잘라낸다 (`_jump_cut_velocity`).
- **낙하 중력 배율**(`fall_gravity_multiplier` = 1.5): 내려올 때만 중력을 키워 '둥실'거림을 줄인다. 기획서에 없던 값이라 이번에 추가했다.

### ⑤ 코요테 타임과 점프 버퍼 — 사람의 실수를 봐주는 장치
- **코요테 타임** (0.1초): 발판 끝에서 살짝 늦게 눌러도 점프된다. 만화에서 절벽을 벗어난 코요테가 잠깐 허공에 떠 있는 데서 온 이름.
- **점프 버퍼** (0.1초): 착지 직전에 미리 눌러도 착지하는 순간 점프된다.
- 둘 다 '남은 시간' 타이머로 구현한다. 매 프레임 `delta`만큼 줄이고, 0보다 크면 유효.

### ⑥ 대시
- 시작하면 0.15초 동안 중력을 무시하고 수평으로 일정 속도(3T ÷ 0.15초 = 20T/s)로 이동한다.
- 처음 0.12초는 무적(`is_invincible`). 아직 맞을 공격이 없어 화면이 밝아지는 것으로만 표시된다.
- 공중 대시는 착지 전까지 1회. 끝난 뒤 0.45초 재사용 대기.
- 잔상: 대시 중 몸통 사각형을 복제해 그 자리에 두고 0.2초 동안 투명해지게 한다.

### ⑦ 조정 수치를 Resource로 분리
`player_tuning.gd`는 "어떤 수치가 있는지" 정의하고, `player_tuning.tres`는 "실제 값"을 담는다. `@export`가 붙은 변수는 에디터 Inspector에 나타나 코드를 열지 않고 수정할 수 있다. 모든 거리는 T 단위로 적고, 코드에서 `GameConst.TILE`(16)을 곱해 픽셀로 바꾼다.

## 4. 검증 결과 (자동 입력 테스트, 60fps 고정)

| 항목 | 기획 값 | 측정 값 | 비고 |
|---|---|---|---|
| 최고 이동 속도 | 7 T/s | 7.0 T/s | 일치 |
| 최대 점프 높이 | 3.5 T | 3.67 T | 약 3px 높음. 1/60초 단위로 끊어 계산하는 데서 생기는 오차 |
| 최소 점프 높이 | 1.2 T | 1.44 T | 버튼을 1프레임 누르는 동안 올라간 높이가 더해짐 |
| 대시 거리 | 3 T | 3.27 T | 대시 후 감속하며 미끄러진 0.27T 포함 |
| 대시 직후 재대시 | 불가 | 불가 | 재사용 대기 동작 확인 |
| 공중 대시 | 1회 | 1회 | 두 번째 입력 무시 확인 |

실제 점프 높이는 실행 화면 왼쪽 위 `last jump`에 표시된다. 수치를 바꿀 때 기준으로 쓰면 된다.

## 5. 실행해서 확인할 것

- [ ] 좌우 이동의 출발·정지가 즉각적인가, 미끄러운가
- [ ] 점프를 길게/짧게 눌러 높이가 확실히 달라지는가
- [ ] 2T·3T 계단은 올라가지고, 바닥에서 4T 기둥은 안 올라가지는가 (3T 계단을 밟고는 올라감)
- [ ] 점프가 둥실거리는가, 너무 빨리 떨어지는가
- [ ] 대시 간격(4T)을 점프 + 공중 대시로 건널 수 있는가
- [ ] 낮은 천장(3T) 아래에서 점프할 때 머리가 막히는 느낌이 자연스러운가
- [ ] 키보드와 패드 둘 다 해보기
