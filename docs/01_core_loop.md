# 01. 핵심 플레이 루프

이 문서는 플레이어가 게임에서 반복하는 행동 흐름을 정의한다. 기준 문서는 `docs/00_game_concept.md`이며, 이 문서와 충돌하는 내용을 두지 않는다.

## 1. 게임 기본 정보

| 항목 | 내용 |
|---|---|
| 게임 제목 | 미정 (가제 미정) |
| 장르 | 2D 메트로배니아 |
| 플랫폼 | PC (Steam 출시 목표) |

## 2. 핵심 플레이 루프 한 문장 요약

플레이어는 신전에서 신의 부탁과 함께 가호를 받고 수업으로 신성을 배운 뒤 마을과 바깥 땅을 탐험하고, 부탁을 완료해 지역의 신앙을 회복시키며 중심 서사를 진전시키고, 수업과 모험으로 얻은 능력으로 이전에 막혀 있던 구간으로 돌아가 새 구역을 열고 다음 수업과 부탁으로 이어간다.

작성 기준 확인:

- 시작 지점: 신전(배움의 공간). 게임을 다시 켜면 마지막 저장 시점부터 시작한다.
- 반복 행동: 탐험과 능력 게이트 확인, 부탁 수행.
- 보상과 성장: 가호(부탁 수령 시 부여) 획득, 수업·모험으로 신성·능력 획득, 자원으로 신성 강화.
- 다음 행동 연결: 새 능력이 이전에 막힌 길 목록을 다음 목적지로 바꾼다.

## 3. 기본 루프 구조

루프는 6단계다. 각 단계 이름은 이 게임의 두 공간(신전 / 마을과 바깥 땅)을 기준으로 붙인다.

기본 형식과의 대응: 준비(배움) → 도전(탐험) → 행동(게이트 확인) → 결과(부탁 수행) → 보상(부탁 완료) → 성장·재도전(역주행)

루프 단계:

배움과 수령(신전) → 탐험(마을·바깥 땅) → 능력 게이트 확인 → 부탁 수행 → 부탁 완료와 보상 → 역주행과 구역 개방 → (배움과 수령으로 복귀)

상세 설명:

플레이어는 신전에서 신의 부탁을 받으며 그 신의 가호를 부여받는다. 해금된 수업을 듣고 신성을 습득한 뒤, 부탁을 수행하러 마을과 바깥 땅으로 나가 미탐험 구간을 탐험한다. 이동 중 통과할 수 없는 지형을 만나면 필요한 능력을 확인하고 지도에 남긴 뒤 다른 경로를 찾는다. 부탁은 전투, 퍼즐 해결, 물건 찾기 등으로 구성되며 보스전이 포함될 수 있다. 부탁을 완료하면 그 지역의 메인 스토리가 클리어되고 지역의 신앙이 회복되며, 병든 신앙의 내막이 드러나 중심 서사가 진전된다. 탐험·전투 중 얻은 자원은 신성 습득과 강화에 쓴다. 수업과 모험으로 새 능력을 얻은 플레이어는 이전에 막혀 있던 구간으로 돌아가 새 구역을 연다. 새 구역은 다음 수업과 다음 부탁으로 이어진다.

고급 신성은 신전 수업에 더해 마을에서 재료를 얻거나 과제를 수행해야 습득한다. 이 조건 때문에 신전과 바깥 땅을 오가는 동선이 루프 안에 들어간다.

## 4. 루프 단계별 정리

| 단계 | 플레이어 행동 | 시스템 반응 | 결과 | 연결 시스템 |
|---|---|---|---|---|
| 1. 배움과 수령 | 신전에서 신의 부탁 수령, 수업 수강, 신성 습득·강화 | 부탁 수령 등록과 가호 부여, 수업 해금 조건(스토리 진행도) 판정, 등급별 습득 조건 확인 | 가호·신성 보유 상태 갱신, 부탁 진행 상태 시작 | 가호 시스템, 수업·신성 습득 시스템, 성장 시스템, 부탁(퀘스트) 시스템, UI 시스템 |
| 2. 탐험 | 마을과 바깥 땅으로 이동, 미탐험 구간 탐색 | 좌우 이동·점프·이동기 입력 처리, 구역 연결 이동, 방문 구간 지도 기록 | 지도 영역 확장, 이동 경로 확보 | 플레이어 조작 시스템, 맵·진행 시스템, UI 시스템 |
| 3. 능력 게이트 확인 | 통과할 수 없는 지형·오브젝트에 접촉 | 게이트의 필요 능력 ID를 보유 능력 목록과 대조해 통과 가능·불가 판정, 미보유 시 부족한 능력 피드백 표시 | 통과 또는 통과 불가. 통과하지 못한 게이트 위치를 지도에 기록 | 능력 게이트 시스템, 가호 시스템, 맵·진행 시스템, UI 시스템 |
| 4. 부탁 수행 | 전투, 퍼즐 해결, 물건 찾기 수행. 보스·강적 처치 | 공격 입력·판정·데미지·사망 처리, 적 감지·이동·공격, 부탁 목표 달성 판정, 자원 지급 | 부탁 진행도 증가, 자원 획득 | 전투 시스템, 적 AI 시스템, 부탁(퀘스트) 시스템, 보상·자원 시스템 |
| 5. 부탁 완료와 보상 | 부탁 목표를 모두 달성 | 부탁 완료 판정, 지역 메인 스토리 클리어 처리, 지역 신앙 회복 상태 갱신, 중심 서사 진전 처리 | 해당 지역 신앙 회복, 이야기 내막 진전. 완료 보상 세부는 미정 (06_아이템·보상에서 결정) | 부탁(퀘스트) 시스템, 맵·진행 시스템, 보상·자원 시스템, UI 시스템 |
| 6. 역주행과 구역 개방 | 이전에 통과하지 못한 구간으로 복귀, 새 능력으로 통과 | 게이트 재판정, 통과 허용, 새 구역 로드, 지도 기록 확장, 저장 | 새 구역 개방. 다음 수업·부탁으로 연결 | 능력 게이트 시스템, 맵·진행 시스템, 저장 시스템, UI 시스템 |

4단계의 전투는 조우 단위로 성립하고 종료된다 (03_전투 시스템 3절).

이 표는 각 단계가 어떤 시스템을 필요로 하는지 판단하는 기준이다. 루프에 등장하지 않는 기능은 우선순위를 뒤로 미룬다.

## 5. 루프에 필요한 주요 시스템

시스템 이름은 00_게임 콘셉트 9절과 일치시킨다. 세부 규칙은 각 상세 문서에서 정의한다.

- 플레이어 조작 시스템: 좌우 이동, 점프, 이동기 입력을 처리한다. 이동기는 일반 대시(기본 보유), 더블점프(해금), 이동 신성(공용 신성, 별도 습득)으로 나뉜다 (세부는 02_플레이어 조작)
- 전투 시스템: 근접 기본공격과 근·원거리 혼합 신성의 입력·판정·데미지·사망을 처리한다. 보스전 판정을 포함한다
- 적 AI 시스템: 적의 감지, 이동, 공격 조건을 처리한다. 세부는 미정 (03_전투 시스템에서 결정)
- 가호 시스템: 보유한 가호를 관리하고, 상황에 따라 하나의 가호를 발현시킨다. 전환은 제단에서만 가능하다
- 능력 게이트 시스템: 지형·오브젝트별 필요 능력을 판정해 통과 가능 여부를 결정한다
- 수업·신성 습득 시스템: 수업 해금 조건(스토리 진행도)을 판정하고, 등급별(초급·고급·현계) 습득 조건을 확인해 신성을 지급한다
- 부탁(퀘스트) 시스템: 부탁 수령, 진행 상태, 완료 판정을 관리한다. 종류는 구분하되 분기는 두지 않는다
- 맵·진행 시스템: 구역 연결, 신계 출입(신전에서만 가능), 지역별 신앙 회복 상태, 지도 기록, 체크포인트, 부활을 관리한다
- 보상·자원 시스템: 탐험·전투·부탁으로 얻는 자원의 지급 조건과 수량을 관리한다. 자원 종류는 미정 (06_아이템·보상에서 결정)
- 성장 시스템: 수업으로 신성을 습득하고, 자원을 소비해 신성을 강화한다
- 저장 시스템: 가호 보유 상태, 신성 상태, 부탁 진행 상태, 지도 기록, 체크포인트 위치를 저장한다. 저장 시점 규칙은 미정 (05_맵·진행에서 결정)
- UI 시스템: HUD, 지도, 신성 화면의 표시와 갱신을 담당한다

상점 시스템은 두지 않는다. 자원 사용처는 신성 습득과 신성 강화뿐이다.

## 6. 루프에 필요한 UI 화면

화면 이름은 00_게임 콘셉트 10절과 일치시킨다. 표시 데이터와 전환 조건은 07_UI 흐름에서 정의한다.

- 타이틀 화면: 신규 시작과 마지막 저장 시점 이어하기의 진입점. 표시 내용 미정
- 인게임 HUD: 체력, 현재 발현 중인 가호, 신성 상태, 일반 대시·신성 쿨타임을 표시한다. 세부 미정
- 지도 화면: 방문 구간, 미탐험 구간, 통과하지 못한 게이트 위치를 구분해 표시한다. 루프 3단계와 6단계를 잇는 화면이다. 세부 미정
- 신성 화면: 보유 신성, 등급, 습득 가능 여부, 보유 자원, 강화 비용을 표시한다. 루프 1단계에서 사용한다. 세부 미정
- 설정 화면: 키 설정과 옵션. 표시 내용 미정

부탁 목록 화면과 인벤토리 화면을 별도로 둘지는 미정이다. (05_맵·진행, 06_아이템·보상에서 결정)

## 7. 루프에 필요한 데이터

데이터 구조는 00_게임 콘셉트 13절 수준까지만 적는다. 구체 수치는 09_데이터 테이블에서 확정한다.

- 플레이어 보유 능력 목록: 능력 ID 집합
- 가호 정의: 가호 ID, 표시 이름, 소속 신. 소속 신은 여우·늑대·용 중 하나. 고유한 이름은 미정
- 능력 게이트 정의: 게이트 ID, 필요 능력 ID, 위치
- 신성 정의: 신성 ID, 등급(초급·고급·현계), 사거리 구분, 쿨타임. 소모 자원 필드는 두지 않는다. 모든 수치 미정
- 습득 조건 정의: 신성 ID, 필요 수업 ID, 필요 스토리 진행도, 필요 재료·과제. 값 미정

저장 대상 데이터는 가호 보유 상태, 신성 상태, 부탁 진행 상태, 지도 기록, 체크포인트 위치다. 각각의 구조는 미정이다. (05_맵·진행에서 결정)
부탁 데이터와 자원 데이터의 구조는 이 문서에서 정의하지 않는다. (05_맵·진행, 06_아이템·보상에서 결정)
방(Room) ID, 출입구 ID, 방 연결 표는 05_맵·진행에서 정의한다.

## 8. 보상과 성장 연결

- 적 처치 보상: 자원을 얻는다. 자원의 이름과 종류는 미정 (06_아이템·보상에서 결정)
- 부탁 완료 보상: 해당 지역의 메인 스토리가 클리어되고 그 지역의 신앙이 회복되며, 병든 신앙의 내막이 드러나 중심 서사가 진전된다. 가호는 완료 보상이 아니라 부탁 수령 시점에 부여된다. 추가 보상(자원 등)은 미정 (06_아이템·보상에서 결정). 신앙은 수치가 아니라 스토리 개념이므로 게이지로 표시하지 않는다
- 보상 사용처: 자원은 신성 습득과 신성 강화에만 쓴다. 상점과 장비 강화는 두지 않는다
- 성장 방식: 두 경로가 혼합된다. 신전 수업으로 신성을 배우는 경로와, 모험 중 이동기 등을 얻는 경로다. 어떤 능력이 어느 경로로 들어오는지는 미정 (04_능력 게이트에서 결정)
- 성장 후 변화: 통과 가능한 게이트가 늘어난다. 도달 가능한 구역과 지도 영역이 넓어진다
- 다음 도전 동기: 통과하지 못하고 지도에 기록해 둔 게이트 목록이 다음 목적지 목록이 된다

## 9. 실패 조건과 재도전 흐름

**목적**
플레이어가 사망해도 탐험 의욕이 꺾이지 않게 한다. 되돌아가기 자체를 벌칙으로 만들지 않는다.

**조건**
플레이어 체력이 0이 되면 사망으로 판정한다. 그 외의 실패 조건은 두지 않는다.

**처리 흐름**

1. 사망을 판정한다.
2. 사망 상태로 전환하고 모든 플레이 입력을 무시한다.
3. 마지막으로 등록된 체크포인트에서 부활시킨다. 체크포인트 거점은 제단으로 확정한다. 배치 간격 등 세부는 미정 (05_맵·진행에서 결정)
4. 부탁 진행 상태, 획득한 자원, 보유 가호·신성을 그대로 유지한다.
5. 마지막 저장 이후의 미저장 탐험 기록(지도 기록 등)만 소실시킨다.
6. 플레이어는 같은 구간에 다시 도전한다.

**예외**

- 자원 차감과 시체 회수 방식은 채택하지 않는다. 화폐형 재화는 두지 않는다.
- 사망 후 적 리스폰 여부는 미정 (05_맵·진행에서 결정)
- 지도 저장 시점 규칙과 소실 범위는 미정 (05_맵·진행에서 결정)
- 별도의 실패 화면을 둘지는 미정 (07_UI 흐름에서 결정)
- 게임을 다시 켤 때는 마지막 저장 시점부터 시작한다.

## 10. 예외 조건

루프에서 실제로 발생 가능한 예외를 정리한다. 처리 방침이 정해지지 않은 항목은 임의로 채우지 않는다.

| 예외 상황 | 발생 조건 | 처리 방침 |
|---|---|---|
| 부탁 완료와 플레이어 사망이 동시에 발생 | 부탁 목표 달성 판정과 체력 0 판정이 같은 프레임에 들어옴 | 처리 방침 미정 (05_맵·진행에서 결정) |
| 가호·신성 중복 지급 | 이미 보유한 가호·신성을 다시 지급하는 처리가 실행됨 | 중복 추가하지 않는다. 보유 능력 목록에 이미 있으면 지급 처리를 중단한다 |
| 부탁 완료 보상 중복 지급 | 완료 처리가 두 번 실행됨 | 부탁 진행 상태를 완료로 확정한 뒤에는 보상 지급을 다시 실행하지 않는다 |
| 저장 실패 | 저장 시점에 파일 쓰기가 실패함 | 처리 방침 미정 (05_맵·진행에서 결정) |
| 불러오기 실패 또는 저장 데이터 없음 | 타이틀 화면에서 이어하기를 선택했으나 데이터를 읽을 수 없음 | 처리 방침 미정 (05_맵·진행, 07_UI 흐름에서 결정) |
| 수업 해금 조건 미충족 | 스토리 진행도가 부족한 상태에서 수업 수강을 시도 | 자원이 충분해도 습득을 허용하지 않는다. 부족한 조건을 표시한다 |
| 고급 신성 재료·과제 미충족 | 수업은 들었으나 마을 재료·과제 조건을 채우지 못함 | 습득을 거부하고 부족한 조건을 표시한다 |
| 자원 부족 상태에서 신성 강화 시도 | 보유 자원이 강화 비용보다 적음 | 강화를 중단하고 자원을 차감하지 않는다. 부족 사실을 표시한다 |
| 부탁 대상물을 부탁 수령 전에 이미 획득 | 물건 찾기 부탁의 대상물을 탐험 중 먼저 획득한 상태에서 부탁을 수령 | 처리 방침 미정 (05_맵·진행에서 결정) |
| 필요 능력 ID가 정의되지 않은 게이트 | 게이트 정의에 필요 능력 ID가 비어 있음 | 통과 불가로 처리하고 오류를 기록한다 |
| 게이트 통과 판정 중 능력 변경 | 판정 진행 중 보유 능력 목록이 갱신됨 | 판정을 다시 수행한다 |
| 사망 상태에서 들어온 모든 플레이 입력 | 사망 판정 이후 입력이 들어옴 | 입력을 무시한다 |
| 체크포인트 미등록 상태에서 사망 | 한 번도 체크포인트를 등록하지 않고 사망 | 처리 방침 미정 (05_맵·진행에서 결정) |
| 능력 없이 진입한 구역에 갇힘 | 진입은 가능하나 탈출 경로가 모두 능력 게이트로 막힘 | 처리 방침 미정 (05_맵·진행, 08_스테이지 설계에서 결정) |
| 신계 출입 조건 위반 | 신전 밖에서 신계 진입을 시도 | 진입을 막는다. 신계 출입은 신전에서만 가능하다 |
| 신계의 게임플레이 역할 | 신계에서 수행 가능한 행동이 정해지지 않음 | 처리 방침 미정 (05_맵·진행에서 결정) |

## 11. MVP 기준 루프

MVP는 "이동 → 막힌 길 확인 → 능력 획득 → 막힌 길 통과"를 최소 1회 검증한다.

MVP 루프:

플레이어 스폰 → 좌우 이동과 점프로 맵 이동 → 진로를 막는 적을 근접 공격으로 처치 → 능력 게이트 접촉, 통과 불가 판정과 부족한 능력 피드백 → 이동기 1종 획득 → 같은 게이트로 복귀 → 통과 허용, 새 구역 진입

MVP 구성 요소:

| 요소 | 범위 |
|---|---|
| 기본 이동 | 좌우 이동, 점프 |
| 기본공격 | 근접 공격 1종 |
| 이동기 | 1종: 더블점프 (02_플레이어 조작에서 확정) |
| 신성 세트 | 한 신의 세트. 어느 신인지 미정 (04_능력 게이트에서 결정). 수업 절차 없이 초기 보유로 지급 |
| 능력 게이트 | 필요 능력을 지정할 수 있는 지형·오브젝트 |

MVP에서 제외할 기능: 자원 획득, 신전 수업과 신성 습득, 신성 강화, 부탁 진행 관리, 보스전, 체크포인트 부활, 지도 기록·저장, 다수의 동물 신과 가호, 난이도 조절.

MVP에서 검증할 질문: 새 능력을 얻은 뒤 이전에 막혀 있던 길을 통과하는 흐름이 재미있는가.

## 12. AI 구현 요청용 루프 요약

**목적**
2D 메트로배니아의 핵심 플레이 루프를 구현한다. 검증 대상은 "새 능력을 얻어 이전에 막혀 있던 길을 통과하고 맵이 확장되는" 반복 흐름이다.

**환경**
Unity 6, C#, PC 단독 실행, 싱글 플레이, 픽셀아트 2D.

**요구 기능**

1. 루프 6단계 진행 관리: 배움과 수령 → 탐험 → 능력 게이트 확인 → 부탁 수행 → 부탁 완료와 보상 → 역주행과 구역 개방.
2. 신전과 마을·바깥 땅 두 공간 사이의 이동 처리.
3. 능력 게이트 판정: 필요 능력 보유 여부로 통과 가능·불가를 결정하고, 불가 시 부족한 능력을 표시한다.
4. 부탁 수령·진행·완료 판정. 분기는 두지 않는다.
5. 부탁 수령 시 해당 신의 가호 부여. 부탁 완료 시 지역 신앙 회복 상태 갱신. 신앙은 수치가 아니라 스토리 개념이다 (내부적으로는 지역별 회복 여부 상태 플래그).
6. 수업 해금 판정(스토리 진행도)과 등급별 신성 습득 조건 확인.
7. 사망 시 체크포인트 부활. 자원과 부탁 진행 상태 유지.
8. 저장: 가호 보유 상태, 신성 상태, 부탁 진행 상태, 지도 기록, 체크포인트 위치.

**데이터 구조**

- 플레이어 보유 능력 목록 (능력 ID 집합)
- 가호 정의 (가호 ID, 표시 이름, 소속 신)
- 능력 게이트 정의 (게이트 ID, 필요 능력 ID, 위치)
- 신성 정의 (신성 ID, 등급, 사거리 구분, 쿨타임) — 소모 자원 필드는 두지 않는다. 모든 수치 미정
- 습득 조건 정의 (신성 ID, 필요 수업 ID, 필요 스토리 진행도, 필요 재료·과제) — 값 미정
- 부탁 데이터와 자원 데이터의 구조는 미정이다. 구체 수치는 09_데이터 테이블에서 확정한다.

**처리 흐름**

1. 신전에서 부탁을 수령하면 그 신의 가호를 부여하고 진행 상태를 시작으로 기록한다.
2. 수업 해금 조건을 판정하고, 조건을 만족하면 신성을 지급한다.
3. 플레이어가 마을과 바깥 땅으로 이동하며 방문 구간을 지도에 기록한다.
4. 게이트 접촉 시 필요 능력 ID를 보유 능력 목록과 대조한다. 보유하면 통과, 미보유면 차단하고 피드백을 표시한다.
5. 부탁 목표(전투, 퍼즐, 물건 찾기)를 달성하면 부탁을 완료 처리한다.
6. 완료 시 지역 신앙 회복 상태를 갱신하고 중심 서사를 진전시킨 뒤 저장한다.
7. 획득한 능력으로 이전 게이트를 재판정하고, 통과하면 새 구역을 로드한다.
8. 새 구역에서 다음 수업과 다음 부탁으로 루프를 반복한다.

**예외 조건**

- 이미 보유한 가호·신성은 중복 지급하지 않는다.
- 부탁 완료 보상은 한 번만 지급한다.
- 스토리 진행도가 부족한 수업은 자원이 충분해도 습득을 허용하지 않는다.
- 고급 신성은 재료·과제 미충족 시 습득을 거부하고 부족한 조건을 표시한다.
- 자원이 부족하면 신성 강화를 중단하고 자원을 차감하지 않는다.
- 필요 능력 ID가 없는 게이트는 통과 불가로 처리하고 오류를 기록한다.
- 게이트 판정 중 능력이 변경되면 판정을 다시 수행한다.
- 사망 상태에서 들어온 이동·공격 입력은 무시한다.
- 사망 시 자원과 부탁 진행 상태는 유지하고, 미저장 탐험 기록만 소실시킨다.
- 신계 진입은 신전에서만 허용한다.
- 부탁 완료와 사망 동시 발생, 저장·불러오기 실패, 체크포인트 미등록 사망, 부탁 대상물 선획득, 구역 갇힘의 처리 방침은 미정이다. 임의로 구현하지 말고 TODO 주석으로 남긴다.

**출력 형식**
Unity 6용 C# 스크립트. 데이터·로직·UI의 책임을 분리한다. 수치는 하드코딩하지 말고 외부 데이터로 분리한다. 미정 항목은 값을 채우지 말고 TODO 주석으로 남긴다.
