# 02. 플레이어 조작

이 문서는 플레이어 입력이 어떤 조건에서 어떤 행동과 상태로 이어지는지 정의한다. 기준 문서는 `docs/00_game_concept.md`와 `docs/01_core_loop.md`이며 두 문서와 충돌하는 내용을 두지 않는다. 데미지 계산과 피격 처리 세부는 03_전투 시스템, 능력 해금 조건은 04_능력 게이트, 화면 표시는 07_UI 흐름, 구체 수치는 09_데이터 테이블에서 정의한다.

## 1. 게임 기본 정보

| 항목 | 내용 |
|---|---|
| 게임 제목 | 미정 (가제 미정) |
| 장르 | 2D 메트로배니아 |
| 플랫폼 | PC (Steam 출시 목표) |
| 개발 엔진 / 언어 | Unity 6 / C# |
| 입력 방식 | 키보드 우선. 게임패드는 지원을 전제로 설계하되 매핑은 미정 (07_UI 흐름에서 결정) |
| 카메라 방식 | 2D 횡스크롤 추적 카메라. 세부는 미정 (08_스테이지 설계에서 결정) |
| 조작 기준 | 월드 좌표 기준 좌우 이동. 플레이어가 직접 이동·점프·공격하고, 발현 중인 가호의 신성을 사용한다 |

입력 처리는 키 재매핑이 가능한 구조로 만든다. 코드에서 키 코드를 직접 참조하지 않고 행동 이름(Move, Jump, Attack 등)으로 참조한다. 키 설정 UI는 07_UI 흐름에서 정의한다.

## 2. 조작 콘셉트

플레이어는 방향키로 좌우 이동하고, Space로 가변 점프를 하며, D로 근접 기본공격을 하고, Shift로 일반 대시를 사용한다. 발현 중인 가호의 공격 신성은 Q/W/E/R/S로, 이동 신성은 A로 사용한다.

설계 기준은 셋이다.

- 기본공격 위주로 전투한다. 참고 게임은 스컬(Skul: The Hero Slayer)이다. 신성은 쿨타임이 길어 난사할 수 없다.
- 이동 능력을 두 층으로 나눈다. 처음부터 가진 기본 능력(좌우 이동, 가변 점프, 일반 대시)과 획득으로 늘어나는 능력(더블점프, 이동 신성)이다.
- 이동 신성은 종족(신)별 신성 구성과 별도 체계로 배운다. 탐험 진행이 어느 종족을 먼저 키우느냐에 종속되지 않게 하기 위함이다.

## 3. 입력 목록

| 기능 | 입력 | 입력 시점 | 설명 | 비고 |
|---|---|---|---|---|
| 좌우 이동 | 방향키 좌·우 | 누르는 동안 유지 | 월드 좌표 기준 좌우 이동 | 공중에서도 방향 전환 가능 |
| 방향키 상·하 | 방향키 상·하 | 미정 | 문·사다리 등 용도 미정 | 미정 (05_맵·진행에서 결정) |
| 점프 | Space | 누르는 순간 시작, 누르는 동안 상승 유지, 떼면 상승 종료 | 가변 점프 | 더블점프 해금 후 공중 1회 추가 |
| 기본공격 | D | 누르는 순간 | 근접 공격 | 판정·데미지는 03_전투 시스템 |

| 상호작용 | F | 누르는 순간 | NPC 대화, 제단, 수업 수강, 가호 전환 | 대상이 범위 안에 있을 때만 |
| 일시정지·메뉴 | Esc | 누르는 순간 | 일시정지 메뉴 열기 | 세부는 07_UI 흐름에서 결정 |

## 4. 이동 기획

### 4-1. 좌우 이동

- 이동 입력: 방향키 좌·우. 이동 방향은 월드 좌표 기준 좌우 2방향이다. 2D 횡스크롤이므로 카메라 기준 이동은 쓰지 않는다.
- 이동 속도: MoveSpeed. 값 미정 (09_데이터 테이블에서 확정)
- 이동 가능 상태: Idle, Move, Jump(공중). 불가능 상태: Dash, Dead. Attack과 Hit 상태의 이동 허용 여부는 미정 (03_전투 시스템에서 결정)
- 애니메이션: 이동 중 Move, 정지 시 Idle. 좌우 입력이 동시에 들어오면 이동 입력이 없는 것으로 처리한다.

### 4-2. 점프 (가변 점프)

- 입력: Space. 누르는 순간 점프를 시작하고, 누르고 있는 동안 상승을 유지하며, 떼면 그 시점에 상승을 종료한다.
- 높이 결정: 누른 시간에 비례해 최소 높이에서 최대 높이 사이로 결정한다.
- 가능 조건: 지면에 닿아 있고 상태가 Idle 또는 Move일 때. 점프 중 좌우 방향 전환을 허용한다.
- 관련 값: JumpPower, JumpHoldMaxTime, AirControlRatio. 값 미정 (09_데이터 테이블에서 확정)

### 4-3. 더블점프 (해금형 능력)

- 획득 방법: 모험 중 획득한다. 신전 수업으로 배우지 않는다. 획득 시점·위치는 미정 (04_능력 게이트, 05_맵·진행에서 결정)
- 입력: 공중에서 Space. 가능 조건은 더블점프를 보유하고, 상태가 Jump(공중)이며, 남은 공중 점프 횟수가 1 이상일 때다.
- 횟수: 공중에서 1회. 착지하면 횟수를 초기화한다. 관련 값 MaxAirJumpCount는 미정 (09에서 확정)
- 미보유 시: 공중 Space 입력을 무시한다. 별도 실패 연출은 두지 않는다.

더블점프는 00_게임 콘셉트의 "MVP 이동기 1종"에 해당한다.

## 5. 공격 기획

### 5-1. 기본공격 (D)

- 공격 입력: D (누르는 순간). 공격 방향은 캐릭터가 바라보는 방향이다.
- 공격 방식: 근접 단타. 연속 입력의 콤보 연결 여부는 미정 (03_전투 시스템에서 결정)
- 공격 판정 범위·쿨타임: AttackRange, AttackCooldown. 값 미정 (09에서 확정)
- 공격 데미지: 미정. 계산식은 03_전투 시스템, 값은 09_데이터 테이블에서 확정한다.
- 공격 가능 상태: Idle, Move, Jump(공중). 불가능 상태: Dash, Dead. Attack 중 재입력과 Hit 중 공격 허용 여부는 미정 (03에서 결정)
- 애니메이션은 Attack이며, 판정은 애니메이션 이벤트로 발생시킨다. 발생 시점(초) 값은 미정 (구조는 03, 값은 09에서 확정)

처리 흐름:

1. D 입력을 받고 현재 상태와 AttackCooldown 경과 여부를 검사한다.
2. 조건을 만족하면 Attack 상태로 전환하고 Attack 애니메이션을 재생한다.
3. 애니메이션 이벤트 시점에 공격 판정을 생성한다. 판정 결과 처리는 03_전투 시스템이 담당한다.
4. 애니메이션이 끝나면 이동 입력이 있으면 Move로, 없으면 Idle로 돌아간다. 공중이면 Jump(공중)로 돌아간다.

### 5-2. 공격 신성 (Q, W, E, R, S)

- 신성 구성: 종족(신)별로 초급 2개 + 고급 2개 + 현계 1개 = 5개다. 여우·늑대·용 세 신 모두 같은 구성이다.
- 사용 범위: 발현 중인 가호의 신성 중 배운 것 전부를 쓸 수 있다. 슬롯 선택은 두지 않는다.
- 키 대응: 배운 신성을 Q, W, E, R, S에 고정 대응시킨다. 대응 순서는 미정 (04_능력 게이트에서 결정)
- 가능 조건: 해당 신성을 배웠고, 발현 중인 가호에 속하며, 쿨타임이 끝났을 때. 소모 자원은 없고 쿨타임만 검사한다.
- 불가능 조건: 미습득, 다른 가호의 신성, 쿨타임 진행 중, Dash·Dead 상태. Attack·Hit 상태의 허용 여부는 미정 (03에서 결정)
- 상태 전환: 공격 신성을 쓰면 Attack 상태로 전환한다. 기본공격과의 Attack 상태 세부 차이(이동 허용, 경직 길이)는 미정 (03에서 결정)

| 등급 | 개수 | 쿨타임 |
|---|---|---|
| 초급 | 2 | 약 10초 (가안) |
| 고급 | 2 | 약 20초 (가안) |
| 현계 | 1 | 60초 이상 (가안) |

이 표는 방향성만 확정한 가안이다. 확정값은 09_데이터 테이블에서 정한다. 기본공격 위주 전투를 유지하기 위해 신성 쿨타임은 길게 잡는다.

## 6. 대시 또는 회피 기획

### 6-1. 일반 대시 (Shift)

- 대시 입력: Shift (누르는 순간). 처음부터 보유하며 신성이 아니고 해금 대상이 아니다. 애니메이션은 Dash다.
- 대시 방향: 미정. 입력 방향 기준인지 바라보는 방향 기준인지 정하지 않았다 (03_전투 시스템에서 결정)
- 대시 거리·지속 시간·쿨타임: DashDistance, DashDuration, DashCooldown. 값 미정 (09에서 확정)
- 무적 시간 여부: 미정 (03_전투 시스템에서 결정)
- 공중 대시 가능 여부: 미정. 도달 범위와 게이트 설계에 직접 영향을 준다 (04_능력 게이트에서 결정)
- 대시 가능 상태: Idle, Move. 불가능 상태: Dash(중복 입력), Attack, Hit, Dead. 쿨타임 진행 중에도 불가능하다.
- 대시 중 충돌 처리: 지형 충돌은 유지한다. 적 통과 허용 여부는 미정 (03에서 결정)

### 6-2. 이동 신성 (A)

- 성격: 마법 이동기다. 종족(신)별 신성 구성과 별도 체계로 배운다. 어느 종족을 먼저 키우든 탐험 진행이 막히지 않게 하기 위함이다.
- 종류·개수: 미정 (04_능력 게이트에서 결정). 쿨타임 값도 미정 (09에서 확정). 확장 키 Z, X, C는 이동 신성이 2개 이상으로 확정될 때만 쓰고, 확정 전에는 A 한 개만 유효하다.
- 가능 조건: 해당 이동 신성을 배웠고 쿨타임이 끝났을 때.
- 불가능 조건: 미습득, 쿨타임 진행 중, Dead 상태. 그 외 상태별 허용 여부는 종류 확정 후 정한다.
- 상태 전환: 미정. 종류가 확정된 뒤 이 문서에 반영한다 (04_능력 게이트에서 결정)

이동 신성은 일반 대시와 다른 능력이다. 일반 대시는 처음부터 가진 기본 능력이고, 이동 신성은 습득 대상이며 능력 게이트 통과 조건으로 쓰인다.

## 7. 아이템 사용 기획

아이템과 인벤토리 구조가 정해지지 않았다. 이 절의 모든 항목이 미정이다. (06_아이템·보상에서 결정) 미정 항목은 아이템 사용 입력, 사용 가능한 아이템, 사용 조건, 사용 결과, 수량 감소 여부, 사용 실패 조건, UI 갱신 조건이다.

아이템 사용 키는 06_아이템·보상에서 구조가 확정된 뒤 3절 입력 목록에 추가한다. 그 전까지 임의의 키를 배정하지 않는다.

## 8. 상호작용 기획

- 상호작용 입력: F (누르는 순간). 가능 거리는 InteractionRange이며 값 미정 (09에서 확정)
- 상호작용 대상: NPC(대화), 제단(체크포인트 거점), 수업, 그 외 오브젝트. 대상 목록 확정은 05_맵·진행에서 한다.
- 가능 상태: Idle, Move. 불가능 상태: Jump(공중), Dash, Attack, Hit, Dead
- 상호작용 결과: 대상별로 대화 시작, 저장, 가호 전환, 수업 수강으로 분기한다. 세부는 05_맵·진행과 07_UI 흐름에서 정의한다.
- 우선순위 규칙: 범위 안에 여러 대상이 있으면 가장 가까운 대상을 우선한다. 상호작용 안내 UI를 표시하며 형식은 07_UI 흐름에서 결정한다.

### 8-1. 가호 전환

- 기본 규칙: 가호 전환은 제단(체크포인트 거점)에서만 가능하다. 제단에서 F로 상호작용해 전환한다.
- 예외 규칙: "자유 가호 전환" 패시브 스킬을 장착하면 전투 중에도 전환할 수 있다. 이 패시브는 획득이 어렵고 패시브 칸 코스트가 크다.
- 전투 중 전환 입력 키: 미정 (04_능력 게이트 또는 07_UI 흐름에서 결정)
- 전환 결과: 발현 중인 가호가 바뀌고 Q/W/E/R/S의 공격 신성 5개가 새 가호의 것으로 교체된다. 쿨타임 인계 여부는 미정 (03에서 결정)

패시브 스킬 시스템: 획득 경로는 탐험 중 획득으로 고정한다. 패시브 칸은 6칸(가안), 자유 가호 전환 패시브 코스트는 2~3칸(가안)이며 확정값은 09_데이터 테이블에서 정한다. 그 외 패시브 목록과 획득 위치는 미정 (04_능력 게이트 또는 06_아이템·보상에서 결정)

|---|---|---|---|---|---|---|---|
| Idle | 가능 | 가능 | 가능 | 가능 | 가능 | 가능 | 가능 |

| Hit | 미정 (03에서 결정) | 미정 (03에서 결정) | 미정 (03에서 결정) | 미정 (03에서 결정) | 미정 (03에서 결정) | 미정 (03에서 결정) | 불가능 |
| Dead | 불가능 | 불가능 | 불가능 | 불가능 | 불가능 | 불가능 | 불가능 |

Hit 상태의 조작 차단 범위는 미정이다. 피격 경직(히트스턴)을 둘지가 조작감에 직접 영향을 주므로 03_전투 시스템에서 논의해 결정한다. 이 문서에서 임의로 정하지 않는다.
피격 시 잠깐의 무적 시간은 확정이다. 무적 시간 값은 미정 (09_데이터 테이블에서 확정).
사망(Dead) 상태에서는 모든 플레이 입력을 무시한다.

상태 전환 조건:

| 전환 | 조건 |
|---|---|
| Idle ↔ Move | 좌우 이동 입력 발생 시 Move, 입력 해제로 이동 속도가 0이 되면 Idle |
| Idle·Move → Jump(공중) | 지면에서 Space 입력 |
| Jump(공중) → Idle·Move | 지면 착지. 이동 입력이 있으면 Move, 없으면 Idle |
| Idle·Move → Dash → 복귀 | Shift 입력과 쿨타임 종료로 진입, 대시 지속 시간 종료로 Idle·Move·Jump(공중)로 복귀 |
| Idle·Move·Jump(공중) → Attack → 복귀 | D 또는 Q/W/E/R/S 입력과 쿨타임 종료로 진입, 공격 애니메이션 종료로 복귀 |
| 모든 상태 → Hit → 복귀 | 피격 판정 발생과 남은 체력이 0보다 클 때 진입. 복귀 조건은 미정 (03에서 결정) |
| 모든 상태 → Dead | 체력이 0 이하 |

## 10. 애니메이션 연결

| 상태 | 애니메이션 | 재생 조건 |
|---|---|---|
| Idle | Idle | 지면에 있고 이동 입력이 없다 |
| Move | Move | 지면에 있고 이동 속도가 0보다 크다 |
| Jump(공중) | Jump / Fall | 상승 중이면 Jump, 하강 중이면 Fall |
| Dash | Dash | Dash 상태 진입 |
| Attack | Attack | Attack 상태 진입. 기본공격과 신성별 구분은 미정 (03에서 결정) |
| Hit | Hit | 피격 판정 발생 |
| Dead | Dead | 체력 0 이하 |

- 애니메이션 이벤트를 사용한다. 기본공격 판정은 애니메이션 이벤트 시점에 생성한다.
- 전환 우선순위: Dead > Hit > Dash > Attack > Jump(공중) > Move > Idle. 상위가 하위를 끊고 재생한다. Attack 중 Hit 발생 시 공격을 취소할지는 미정 (03에서 결정). 결정 전까지 이 우선순위를 임시 기준으로 쓴다.
- 더블점프는 Jump 애니메이션을 처음부터 다시 재생한다. 별도 애니메이션을 둘지는 미정 (04에서 결정).

## 11. UI 안내

세부 화면 구성은 07_UI 흐름에서 정의한다. 이 절은 조작이 요구하는 표시 항목만 적는다.

- 쿨타임 표시: 공격 신성 5개, 이동 신성, 일반 대시의 남은 쿨타임을 표시한다.
- 가호 표시: 현재 발현 중인 가호와 그 가호의 신성 5개를 HUD에 표시한다.
- 상호작용 안내: 상호작용 가능한 대상이 범위 안에 있으면 안내를 표시한다.
- 입력 불가 안내: 쿨타임 중 입력과 미습득 신성 입력에 짧은 피드백을 표시한다. 형식은 미정 (07에서 결정)
- 조작 안내: 표시한다. 표시 시점과 형식은 미정 (07에서 결정). 아이템 수량 표시는 미정 (06·07에서 결정), 튜토리얼 메시지는 미정 (08_스테이지 설계에서 결정)

## 13. 필요한 데이터

필드 이름만 정의한다. 모든 값은 미정이며 09_데이터 테이블에서 확정한다. 시간 단위는 초, 거리 단위는 유닛으로 통일한다.

| 분류 | 필드 | 참조하는 시스템 |
|---|---|---|
| 이동·점프 | MoveSpeed, AirControlRatio, JumpPower, JumpHoldMaxTime, MaxAirJumpCount | 이동 계산, 점프·더블점프 |
| 대시 | DashDistance, DashDuration, DashCooldown | 일반 대시 |
| 공격 | AttackRange, AttackCooldown, AttackHitTiming | 기본공격 판정 |
| 신성 | DivinityCooldown (등급별) | 공격 신성·이동 신성 |
| 피격 | HitInvincibleTime | 피격 무적 |
| 상호작용 | InteractionRange | 상호작용 판정 |
| 성장 | PassiveSlotMax, FreeBlessingSwitchCost | 패시브 칸과 가호 전환 |
| 능력치 | MaxHp, CurrentHp, AttackPower | 전투 (항목 정의는 03_전투 시스템) |

AttackHitTiming은 공격 애니메이션 시작 후 판정이 발생하는 시점이다. 능력치의 계산 규칙과 값 범위는 03_전투 시스템과 09_데이터 테이블에서 정의한다. 이 문서는 필드 이름과 참조 위치만 고정한다.

## 14. AI 구현 요청용 프롬프트

**목적**
2D 메트로배니아의 플레이어 조작 시스템을 구현한다. 입력을 상태·행동·애니메이션으로 연결하고, 가능·불가능 조건을 코드에 반영한다.

**환경**
Unity 6, C#, PC 단독 실행, 싱글 플레이, 2D 횡스크롤 픽셀아트. 입력은 키보드 우선이며 게임패드 확장을 전제로 키 재매핑이 가능한 구조로 만든다.

**요구 기능**

1. 좌우 이동: 방향키. 월드 좌표 기준 2방향. 공중에서도 방향 전환을 허용한다.
2. 가변 점프: Space를 누르는 순간 점프를 시작하고, 누르는 동안 상승을 유지하며, 떼면 상승을 종료한다.
3. 더블점프: 해금형 능력. 보유 시 공중에서 1회 추가 점프하고, 착지 시 횟수를 초기화한다.
4. 기본공격: D. 근접 공격. Attack 상태로 전환하고 애니메이션 이벤트 시점에 판정을 생성한다.
5. 공격 신성: Q/W/E/R/S. 발현 중인 가호의 배운 신성만 사용한다. 소모 자원 없이 쿨타임만 검사한다.
6. 이동 신성: A. 종족 신성과 별도 체계로 습득한다. 종류가 미정이므로 습득 여부와 쿨타임 검사 구조만 만든다.
7. 일반 대시: Shift. 처음부터 보유하는 기본 능력이며 쿨타임을 가진다.
8. 상호작용: F. 범위 안에서 가장 가까운 대상과 상호작용한다. 제단에서 가호를 전환한다.
9. 상태 머신: Idle, Move, Jump(공중), Dash, Attack, Hit, Dead 7종. 상태를 추가하지 않는다.

**데이터 구조**

- 플레이어 능력치: MoveSpeed, AirControlRatio, JumpPower, JumpHoldMaxTime, MaxAirJumpCount, DashDistance, DashDuration, DashCooldown, AttackRange, AttackCooldown, AttackHitTiming, HitInvincibleTime, InteractionRange
- 보유 능력 목록: 능력 ID 집합 (더블점프, 이동 신성 포함)
- 가호 정의: 가호 ID, 소속 신(여우·늑대·용), 소속 신성 ID 5개
- 신성 정의: 신성 ID, 등급(초급·고급·현계), 쿨타임. 소모 자원 필드는 두지 않는다
- 패시브 정의: 패시브 ID, 코스트, PassiveSlotMax. 모든 수치는 외부 데이터로 분리하고 하드코딩하지 않는다

**처리 흐름**

1. 입력을 행동 이름으로 받는다. 키 코드를 직접 참조하지 않는다.
2. 현재 상태와 쿨타임, 보유 능력을 검사한다.
3. 조건을 만족하면 상태를 전환하고 해당 행동을 실행한다.
4. 상태에 대응하는 애니메이션을 재생한다. 공격 판정은 애니메이션 이벤트로 생성한다.
5. 행동이 끝나면 이동 입력 유무와 접지 여부에 따라 Idle, Move, Jump(공중) 중 하나로 돌아간다.

**예외 조건**

- Dead 상태에서 모든 플레이 입력을 무시한다. UI 팝업, 일시정지, 로딩 중에도 플레이 입력을 차단한다.
- 쿨타임 중 입력, 미습득 신성 입력, 발현 중이 아닌 가호의 신성 사용은 모두 무시한다. 입력 버퍼(선입력)와 접지 유예는 미정이므로 TODO 주석으로 남긴다.
- 더블점프 미보유 또는 횟수 소진 상태의 공중 Space 입력, 대시 중 대시 재입력, 대상 없는 F 입력을 무시한다.
- 좌우 동시 입력은 이동 없음으로 처리한다. 같은 프레임 다중 입력의 우선순위는 대시 > 공격·신성 > 점프 > 이동이다.
- 제단이 아닌 곳의 가호 전환은 자유 가호 전환 패시브 장착 시에만 허용한다.
- Hit 상태의 입력 차단 범위, 대시 방향과 무적 여부, 공중 대시 허용 여부, 이동 신성의 상태 처리는 미정이다. 임의로 구현하지 말고 TODO 주석으로 남긴다.

**출력 형식**
Unity 6용 C# 스크립트. 입력, 이동, 전투, 상태 머신, 능력치를 각각 분리한 구조로 작성한다. 입력은 PlayerInputController, 이동은 PlayerMovement, 전투는 PlayerCombat, 상태는 PlayerStateMachine, 능력치는 PlayerStats로 책임을 나눈다. 데이터와 로직을 분리하고, 수치는 ScriptableObject 등 외부 데이터로 뺀다. 미정 항목은 값을 채우지 말고 TODO 주석으로 남긴다.
