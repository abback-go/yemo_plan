## 15.1 엔진과 선택 근거

| 항목 | 내용 |
|---|---|
| 엔진 | **Godot 4** — 버티컬 슬라이스까지 [확정]. 전역 시점에 Unity 전환 여부를 다시 판단 [확정] |
| 버전 | 4.7 계열 [미결정: 착수 시 공식 사이트에서 최신 안정판 확인] |
| 스크립트 언어 | **GDScript** — Godot 4의 C# 프로젝트는 웹 내보내기를 정식 지원하지 않아 웹 빌드 테스트에 불리함 |
| 선택 근거 | ① 약 65~90MB, 설치 없이 실행 → 사지방에서 매일 작업 가능 (Unity 6 에디터는 약 8.5GB, 사용자 보고) ② 클라우드에서 명령어로 웹 빌드 가능 → 사지방 브라우저에서 플레이 테스트 [후보] ③ 씬 파일(`.tscn`)이 짧은 텍스트라 git·AI 협업에 유리 ④ MIT 라이선스, 무료 |
| 감수할 점 | 산나비급 정밀 2D 액션의 Godot 레퍼런스·에셋이 Unity보다 적음 (산나비·이나리의 사용 엔진은 미확인). 유료 에셋 판매는 Godot 공식 스토어에서 아직 미지원 (보도 기준) |
| 엔진 전환 시점 검증 | 버티컬 슬라이스 초반 1~2주의 **손맛 프로토타입**(이동·점프·검 공격·적 1종·히트스톱·화면 흔들림)으로 품질을 확인. 아니다 싶으면 이 시점에 전환 |

### 15.1.1 엔진 이식성 원칙 [제안]

전역 후 Unity로 전환할 경우를 대비해, 엔진에 묶이지 않는 형태로 만든다.

| 대상 | 방식 |
|---|---|
| 레벨 | 외부 레벨 에디터 **LDtk**로 제작 (Godot용 임포터, Unity용 LDtkToUnity 모두 존재) |
| 적·아이템·수치 데이터 | JSON / CSV로 엔진 밖에서 관리 |
| 이미지 | 엔진 전용 형식이 아닌 일반 스프라이트 시트(PNG) |
| 검증된 수치 | 기획서(5장 파라미터 표)에 기록 |
